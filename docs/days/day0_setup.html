Day 0 - Technical setup for a reproducible NGS workshop

Accounts, software, containers, and readiness checks

Overview

This preparatory session ensures that every participant has a working computational environment before the start of the workshop. Personal computers are preferred, but if limitations or installation issues arise, participants will be able to use computers from the University.

The goal is not to learn bioinformatics yet. Instead, we will verify that the required software is installed correctly and that containers can access files on the local computer.

What you will have ready today

By the end of Day 0, you should be able to:

  • access GitHub;
  • access Docker Hub;
  • install and open Visual Studio Code;
  • install Git and verify that it works;
  • install Docker and verify that it can run a container;
  • install and open IGV.

These steps should be completed before the start of the workshop.

For any problems, questions, or installation issues, follow the issue-reporting instructions at the end of this page.

Conceptual background and setup checklist

NGS analyses depend on many linked components: input data, reference files, software tools, command-line options, and output files. Small differences in any of these components can change the final results.

For Day 0, the goal is to create accounts, install the required software, and verify the tools needed to work in a reproducible project folder. The table below combines the setup checklist with the reason each component matters.

Order Action Component Basic idea Why it matters
1 Create or verify account GitHub Online platform for Git repositories. Gives access to the workshop material and stores a remote copy of your work.
2 Create or verify account Docker Hub Online registry for container images. Provides access to container images used to run bioinformatics software.
3 Install and open Visual Studio Code Code editor with an integrated terminal. Provides one place to edit scripts, write notes, and run commands.
4 Install and check Git Version-control tool for text files. Records changes in scripts, metadata, and documentation.
5 Install and check Docker Container engine used to run software images. Keeps command-line tools and dependencies consistent across computers.
6 Install and open IGV Genome browser for visual inspection of genomic data. Allows inspection of aligned sequencing data and genomic regions.

The detailed repository structure will be covered in Day 1. For now, we will focus on the intuitive reasons why we use Git, containers, Visual Studio Code, and IGV in a reproducible NGS workflow.

NoteHow this setup will be used

We will use Visual Studio Code as the main working environment. VS Code is a versatile and widely used code editor that lets you organize files, browse folder contents, edit scripts and notes, open terminals, run container commands, and inspect outputs such as text files, PDFs, PNGs, and HTML reports.

Because the software tools will be provided through Docker images, you do not need to install R, RStudio, Python, Bioconductor packages, or command-line bioinformatics tools directly on your computer for the workshop. Those programming languages and tools will run inside the relevant container image.

The preferred route is to run the practical commands locally with Docker. If this is not possible because of laptop, storage, or installation limitations, we may provide University computers and checkpoint files so that you can still follow the workflow and document the analysis.

2.1 Windows 10/11

The supported Windows route is:

Windows 10/11 -> WSL2 Ubuntu -> Docker Desktop with WSL2 integration -> VS Code connected to WSL -> IGV

The goal is to run all workshop commands from an Ubuntu Linux terminal, opened inside Visual Studio Code.

Windows will still be used for desktop applications such as Docker Desktop, Visual Studio Code, and IGV. The command-line analysis will run inside Ubuntu through WSL2.

Component Where it runs What it does
Visual Studio Code Windows The editor application.
WSL extension for VS Code Windows and WSL Lets VS Code open files and terminals inside Ubuntu.
Ubuntu WSL2 Linux environment inside Windows The place where workshop shell commands run.
Docker Desktop Windows, integrated with WSL2 Provides the docker command inside Ubuntu.
IGV Desktop Windows Genome browser used for visual inspection.

Do not run workshop commands from PowerShell, CMD, Git Bash, Anaconda Prompt, or a normal Windows terminal after setup. Use the VS Code terminal connected to Ubuntu WSL.

The workshop project should be created inside the Ubuntu filesystem:

~/workshop_ngs

Do not create the workshop project under:

/mnt/c/...

This avoids common path, permission, mount, and file-speed problems.

Also avoid OneDrive, Dropbox, iCloud Drive, network-mounted folders, and paths with spaces for the main workshop project. These locations can cause slow file access, permission problems, and Docker mount errors.

Step 1: install WSL2 and Ubuntu

Open Windows Terminal or PowerShell as administrator.

Run:

wsl --install

This installs WSL and the default Ubuntu distribution. The one-command route requires a supported, up-to-date version of Windows 10 or Windows 11. If this command is not available or does not work on your computer, follow the official Microsoft WSL installation instructions.

If WSL is already installed but Ubuntu is missing, list the available distributions and install Ubuntu explicitly:

wsl --list --online
wsl --install -d Ubuntu

If Windows asks you to restart, restart the computer.

After restart, Ubuntu may open automatically. If not, open Ubuntu from the Windows Start menu. (Look for the Linux penguin icon)

The first time Ubuntu starts, it will ask you to create:

  • a Linux username;
  • a Linux password.

This password is used for Ubuntu commands such as sudo. It is not your Windows password and it is not your GitHub password.

Step 2: check that Ubuntu uses WSL2

Open Windows Terminal or PowerShell, update WSL, record its version, and check that Ubuntu is using WSL2:

wsl --update
wsl --version
wsl -l -v

Example output:

  NAME      STATE           VERSION
* Ubuntu    Running         2

The distribution name may be Ubuntu, Ubuntu-24.04, or something similar, and its state may be Running or Stopped. The important value is 2 in the VERSION column. If Ubuntu shows version 1, ask for help before continuing.

Docker Desktop requires a recent WSL release. If wsl --version is not recognized or the update fails, complete the current Microsoft WSL update instructions before installing Docker Desktop.

Step 3: update Ubuntu and install basic command-line tools

Open Ubuntu from the Windows Start menu.

Run:

sudo apt update
sudo apt install -y git gawk curl wget ca-certificates unzip

Check Git:

git --version

Expected output:

git version 2.x.x

The exact version number may be different.

Step 4: install Docker Desktop for Windows

Install Docker Desktop for Windows. Depending on which version of Windows you are using, Docker Desktop may prompt you to turn on WSL 2 during installation. Read the information displayed on the screen and turn on the WSL 2 feature to continue.

Do not install Docker Engine or the Docker CLI with apt inside Ubuntu WSL. Docker documents that a second Docker installation inside the WSL distribution can conflict with Docker Desktop’s WSL integration.

Open Docker Desktop after installation.

In Docker Desktop settings:

  1. Go to Settings -> General.
  2. Make sure Use the WSL 2 based engine is enabled. On current installations this may already be enabled and the setting may not be shown.
  3. Go to Resources -> WSL integration.
  4. Enable integration with Ubuntu.
  5. Click Apply & restart if requested.

Step 5: test Docker from Ubuntu

Open the Ubuntu terminal.

Run:

docker --version
docker run --rm hello-world

The first time you run this command, Docker may first download the small hello-world image. Output similar to this is normal:

Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
...
Status: Downloaded newer image for hello-world:latest

Hello from Docker!
This message shows that your installation appears to be working correctly.

The exact digest, platform, and download details may be different.

This confirms that Docker Desktop is correctly connected to Ubuntu WSL.

If docker is not found, open Docker Desktop settings again and check:

Resources -> WSL integration -> Ubuntu enabled

Step 6: install Visual Studio Code

Install Visual Studio Code for Windows.

During installation, retain the option that adds the code command to PATH, if it is offered.

Open Visual Studio Code once after installation.

Step 7: install the WSL extension in VS Code

In Visual Studio Code:

Extensions -> search "WSL" -> install "WSL" by Microsoft

Useful reference: Use WSL in Visual Studio Code

Step 8: connect VS Code to Ubuntu WSL

In Visual Studio Code, use:

Ctrl + Shift + P -> WSL: Connect to WSL

or:

Remote Explorer -> WSL -> Ubuntu

Open a new terminal:

Terminal -> New Terminal

The terminal should show a Linux-style prompt, for example:

your_username@computer_name:~$

Check:

pwd

Expected output:

/home/your_username

If the prompt looks like this:

PS C:\Users\your_username>

you are still in a Windows terminal. Reconnect VS Code to WSL before continuing.

Step 9: create the workshop folder inside Ubuntu

In the VS Code terminal connected to Ubuntu WSL, run:

mkdir -p ~/workshop_ngs
cd ~/workshop_ngs
pwd

Expected output:

/home/your_username/workshop_ngs

Open this folder in VS Code:

code .

If VS Code asks whether to reopen the folder in WSL, accept.

After this, the Explorer panel should show the workshop_ngs folder, and the terminal should still show a Linux-style prompt.

Step 10: open the Ubuntu folder from Windows Explorer

Keep the workshop project inside Ubuntu WSL. This is the safest location for Linux commands, Git, Docker mounts, and file permissions.

You can still browse the same folder with normal Windows clicks when you need to open a table, HTML report, PDF, or image with a Windows program such as Excel, Edge, or IGV.

From the VS Code terminal connected to Ubuntu WSL, run:

explorer.exe .

Windows File Explorer will open the current Ubuntu folder. You will be able to double-click small output files from there, like those we will generate under the folders:

raw_data/metadata/*.csv
results/logs/day1/fastp/*.fastp.html
results/day2_rnaseq/counts/*.tsv
results/day2_rnaseq/deseq2/*.tsv

You can also paste this kind of path into the Windows Explorer address bar:

\\wsl.localhost\Ubuntu\home\your_username\workshop_ngs

If your Ubuntu distribution has a slightly different name, open Windows Explorer and type:

\\wsl.localhost\

Then click into the Ubuntu distribution, then home, then your username, then workshop_ngs.

Important rule: use Windows Explorer for browsing and opening results, but run workshop commands from the VS Code terminal connected to Ubuntu WSL.

Step 11: test folder mounting with Docker

In the VS Code terminal connected to Ubuntu WSL, first move into the workshop folder:

cd ~/workshop_ngs
mkdir -p test_mount
echo "Docker can read this file" > test_mount/message.txt

Then run:

docker run --rm \
  --platform linux/amd64 \
  -v "$PWD:/work" \
  -w /work \
  alpine:latest \
  cat test_mount/message.txt

Expected output:

Docker can read this file

This confirms that Docker can mount the Ubuntu WSL project directory into a Linux container using the same linux/amd64 platform and /work location used later in the workshop.

Remove the temporary mount-test files:

rm test_mount/message.txt
rmdir test_mount

Step 12: install IGV on Windows

Install IGV Desktop on Windows and choose the Windows package that includes Java.

Open IGV once to confirm that it starts correctly.

3. Expected outputs and Day 0 readiness checklist

Day 0 produces a working local environment, not NGS analysis files or biological results. You are ready for Day 1 if you can confirm all of the following:

  • You can log in to GitHub.
  • You can log in to Docker Hub.
  • Visual Studio Code opens correctly.
  • Windows users can open a VS Code terminal connected to Ubuntu WSL.
  • macOS and Linux users can open a terminal from the workshop_ngs folder.
  • git --version prints a Git version.
  • gawk --version, curl --version, and wget --version run successfully.
  • docker --version prints a Docker version.
  • docker run --rm hello-world completes successfully.
  • The linux/amd64 Docker mount test prints Docker can read this file.
  • IGV opens correctly.

4. Git checkpoint

No Git commit is expected on Day 0. The workshop_ngs directory is only a local folder at this stage. Day 1 initializes it as a Git repository, creates the required project structure and .gitignore, and makes the first commit.

5. Common problems

Problem Likely cause What to check
The VS Code terminal starts with PS C:\... VS Code is still connected to Windows rather than Ubuntu WSL Reopen the folder with WSL: Connect to WSL and confirm that pwd starts with /home/
docker is not found inside Ubuntu WSL Docker Desktop is not running or WSL integration is disabled Docker Desktop Settings -> Resources -> WSL integration
Docker cannot connect to its daemon Docker Desktop or the native Linux Docker service is not running Start Docker Desktop, or follow the service instructions for your Linux distribution
Docker reports a permission error on Linux The current user cannot access the Docker socket Follow the official Linux post-installation guidance; do not rely on sudo docker for workshop commands
hello-world works but the mount test fails The command was run outside ~/workshop_ngs, the folder was not shared, or linux/amd64 emulation is unavailable Check pwd, Docker Desktop file sharing/emulation settings, and the exact mount command
code . is not found The VS Code command-line launcher is not on PATH Open VS Code manually and use File -> Open Folder
IGV does not start The wrong package was downloaded or a non-bundled installation lacks a current Java runtime Use the platform-specific IGV download; current non-bundled releases require Java 21 or newer
