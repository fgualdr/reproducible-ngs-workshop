2. Overview of the day

Today we reuse the mapping logic from Day 2, then introduce ChIP-seq-specific quality control, peak calling, replicate reproducibility and differential occupancy analysis.

The teaching sequence is therefore:

  1. map and filter reads;
  2. assess mapped-library quality with strand cross-correlation;
  3. make fragment-coverage tracks;
  4. call peaks with MACS3 without input and optionally with matched ΔHP1021 ChIP as a target-negative control;
  5. perform three complementary post-peak QC checks: IDR, replicate signal correlation and FRiP;
  6. merge significant peaks into one common peak set;
  7. count the six selected WT/WTS samples over the same genomic intervals;
  8. inspect the common count matrix with PCA;
  9. test differential peak occupancy with DESeq2;
  10. visualize ChIP-seq signal around peaks;
  11. extract peak sequences and perform de novo motif discovery with STREME.

This order separates distinct QC questions:

Does one library show the expected strand-shift enrichment structure? -> strand cross-correlation
Are ranked peak calls reproducible between biological replicates?      -> IDR
Do replicate genomic signal profiles agree globally?                   -> replicate correlation
What fraction of usable fragments falls inside called peaks?           -> FRiP
Do common peak counts show sensible sample structure?                   -> PCA
Which common peaks change by condition?                                 -> DESeq2
WarningWorkshop analysis, not a reproduction of the paper

The publication and this workshop do not use the same reference, sample set or statistical workflow. All available ChIP-seq libraries are mapped to GCF_025998455.1. The core exercise calls peaks without an external control and compares only WT and WTS for the downstream occupancy analysis; an additional, separate exercise uses ΔHP1021 ChIP as a target-negative MACS3 control for WT, if the immunoprecipitated target is HP1021. These are teaching analyses, not a reproduction of the published peak coordinates or biological conclusions.

3. Map and filter the ChIP-seq reads

ChIP-seq reads come from genomic DNA fragments recovered by immunoprecipitation. Mapping asks where those fragments originate on the reference genome.

We use Bowtie2 to align the paired-end reads and SAMtools to convert, sort, filter and index the alignments. These are the same basic alignment objects introduced on Day 2.

The transformation is:

paired FASTQ
  -> Bowtie2 alignments
  -> temporary SAM
  -> coordinate-sorted BAM
  -> filtered BAM
  -> BAM index and mapping summaries

The sorted BAM preserves the complete mapped library. The filtered BAM is the working file for ChIP-seq QC, coverage tracks, peak calling and peak counting.

3.1 Mapping and filtering script

Create scripts/day3_chipseq/01_map_bowtie2_sort_filter.sh:

#!/usr/bin/env bash
set -euo pipefail

fastq_dir="results/day1_qc/trimmed_fastq/chipseq"
index_prefix="reference_genome/bowtie2_index/genome"
bam_dir="results/day3_chipseq/bam"
log_dir="results/logs/day3"

for read1 in "${fastq_dir}"/*_R1.trimmed.fastq.gz
do
  read2="${read1/_R1.trimmed.fastq.gz/_R2.trimmed.fastq.gz}"
  sample_id="$(basename "${read1}" _R1.trimmed.fastq.gz)"
  sam_file="${bam_dir}/${sample_id}.sam"
  sorted_bam="${bam_dir}/${sample_id}.sorted.bam"
  filtered_bam="${bam_dir}/${sample_id}.filtered.bam"

  bowtie2 \
    -x "${index_prefix}" \
    -1 "${read1}" \
    -2 "${read2}" \
    -p 2 \
    -S "${sam_file}" \
    2> "${log_dir}/${sample_id}.bowtie2.log"

  samtools sort \
    -@ 2 \
    -O BAM \
    -o "${sorted_bam}" \
    "${sam_file}"

  samtools index "${sorted_bam}"
  samtools flagstat "${sorted_bam}" > "${log_dir}/${sample_id}.flagstat.txt"

  samtools view \
    -@ 2 \
    -b \
    -q 10 \
    -f 2 \
    -F 2828 \
    -o "${filtered_bam}" \
    "${sorted_bam}"

  samtools index "${filtered_bam}"
  samtools flagstat "${filtered_bam}" > "${log_dir}/${sample_id}.filtered.flagstat.txt"

  rm -f "${sam_file}"
done

3.2 What the filter means

The key command is:

samtools view -b -q 10 -f 2 -F 2828
Option Meaning here
-b write BAM output
-q 10 require mapping quality of at least 10
-f 2 retain alignments belonging to properly paired fragments
-F 2828 remove unmapped, mate-unmapped, secondary, failed-QC and supplementary records

samtools sort accepts SAM directly and writes coordinate-sorted BAM; -O BAM simply makes the output format explicit. The -b option belongs to samtools view, not to samtools sort.

Duplicates are retained in this workshop. A pileup of identical coordinates may reflect PCR amplification, but a strong narrow binding event can also generate repeated fragment coordinates. A research analysis should decide how to handle duplicates after inspecting library complexity and peak behaviour rather than applying one rule mechanically.

4. Quality control of mapped ChIP-seq libraries

ChIP-seq QC is not one number. We combine several pieces of evidence:

Question Evidence
Did the reads map to the intended reference? Bowtie2 log and samtools flagstat
Are the paired fragments plausible? proper-pair rate and fragment-size summaries
Does the library contain strand-shift enrichment structure? strand cross-correlation
Is enrichment visible as genomic signal? CPM bigWig tracks
Do biological replicates reproduce peak calls? IDR after peak calling
Do replicate signal profiles agree genome-wide? deepTools replicate correlation after peak calling
Is ChIP signal concentrated in called peaks? FRiP after peak calling

4.1 Strand cross-correlation: the idea

For a narrow ChIP-seq binding event, DNA fragments overlap the bound locus. The 5′ ends of reads mapping to the + strand tend to accumulate on one side of the event, while reads mapping to the - strand tend to accumulate on the other side.

Strand cross-correlation asks how similar those two strand-specific read-start profiles become when one profile is shifted relative to the other:

  1. keep the +-strand profile fixed;
  2. shift the --strand profile by increasing distances;
  3. calculate the correlation at each shift;
  4. inspect where the correlation reaches local maxima.

Two positions on the curve are particularly useful:

  • the phantom peak, usually close to the sequencing read length;
  • the fragment-length peak, near the characteristic separation of the two sides of enriched ChIP fragments.

For example, with 50 bp reads from a library whose sonicated fragments are around 350 bp, the phantom peak is expected near 50 bp and the enrichment-associated fragment peak near 350 bp.

A library with clear enrichment usually shows a fragment-length peak that rises above the read-length phantom structure. This is a QC pattern, not an absolute biological rule: low-complexity experiments or proteins with very few genuine binding sites can also produce modest cross-correlation values.

The commonly reported quantities are:

Quantity Interpretation
estFragLen shift of the strongest non-phantom cross-correlation peak
phantomPeak read-length-associated peak position
NSC correlation at the fragment peak divided by the minimum cross-correlation
RSC fragment-peak enrichment above the minimum, relative to the phantom-peak enrichment above the minimum
QualityTag thresholded summary derived from RSC; useful as a warning flag, not as the complete QC decision
NotePaired-end interpretation

For paired-end data, the physical fragment boundaries are already defined by the two mates. MACS3 BAMPE therefore does not need the cross-correlation estimate in order to reconstruct fragment length. We use strand cross-correlation as an independent measure of enrichment structure and library quality.

4.2 phantompeakqualtools

We calculate strand cross-correlation with phantompeakqualtools, the Kundaje Lab implementation widely used in ENCODE-style ChIP-seq QC. The tool is built around the SPP strand cross-correlation framework described by Kharchenko, Tolstorukov and Park (2008) and the ENCODE ChIP-seq QC recommendations of Landt et al. (2012).

Its main script, run_spp.R, reads mapped tags, constructs strand-specific read-start profiles, evaluates their cross-correlation over a range of shifts and reports the fragment peak, phantom peak, NSC, RSC and quality tag. With -savp it also writes a PDF cross-correlation curve for visual inspection.

The original method was developed around tag/read starts. For our paired-end data, the directly observed mate-to-mate fragment length remains the physical fragment definition; we use cross-correlation as an independent enrichment-structure QC measurement. We use only the QC functionality of phantompeakqualtools; peak calling in this workshop is performed with MACS3.

4.3 Make CPM-normalized fragment coverage with bamCoverage

bamCoverage from deepTools converts BAM alignments into an indexed bigWig signal track.

For paired-end ChIP-seq we want fragment coverage rather than two independent read tracks:

  • --extendReads uses the mate positions to represent the complete paired-end fragment;
  • --samFlagInclude 64 keeps only read 1 as the representative BAM record, so that the same physical fragment is not added twice;
  • --normalizeUsing CPM scales the track by the number of mapped observations used to generate the signal.

Create scripts/day3_chipseq/03_make_cpm_bigwigs.sh:

5. Call peaks with MACS3

Peak calling converts a continuous ChIP-seq enrichment signal into genomic intervals whose signal is unlikely to be explained by the estimated background alone.

We use MACS3 callpeak, the current implementation of the MACS peak-calling framework.

5.1 From a paired-end BAM to a peak

For paired-end ChIP-seq, MACS3 can be understood as four linked operations:

  1. Build the observed ChIP signal. With -f BAMPE, each properly mapped read pair already defines the physical DNA fragment. MACS3 piles up those observed fragments across the genome to obtain the treatment signal, \(k(x)\).
  2. Build an expected background. MACS3 calculates an expected count, \(\lambda(x)\), representing how much signal could plausibly occur without specific enrichment. The source of this background depends on whether a control is supplied; this is explained in Section 5.2.
  3. Score enrichment across the genome. At each genomic position, the observed treatment pileup is compared with the expected background using a local Poisson model. This produces a genome-wide p-value score track, which MACS3 converts to q-values when peak calling is performed with -q.
  4. Turn the score track into genomic intervals. MACS3 keeps regions above the selected score threshold, merges nearby significant segments when the intervening gap is sufficiently short, rejects regions shorter than the minimum peak length, and reports the resulting intervals as peaks. With --call-summits, local maxima inside those intervals are also reported.
paired-end BAM
      |
      v
observed fragments -> treatment pileup k(x)
      |
      +-----------------------------+
                                    |
background model -> lambda(x)       |
      |                             |
      +---------- compare ----------+
                  |
                  v
          Poisson p-value track
                  |
                  v
              q-values
                  |
                  v
      threshold + join nearby regions
                  |
                  v
        peak start -- summit -- peak end

ImportantMACS3 isliding

The fragment length contributes to the treatment/background model and, by default, to the minimum allowed peak length. Peak boundaries come from contiguous parts of the statistical score track that pass the selected cutoff. The default maximum gap used to join nearby significant segments is based on the detected read length, whereas the default minimum peak length is based on \(d\).

What happens to the MACS shifting model with paired-end data?

The original MACS model was designed for single-end ChIP-seq. Plus- and minus-strand read starts form two displaced clouds around a binding event like the Phantompeak QC step!, and MACS estimates their separation to infer the fragment length and shift the tags appropriately.

With -f BAMPE, that inference is unnecessary for the treatment pileup: the two mates already define the complete fragment. MACS3 therefore enters its paired-end mode and uses the actual insert sizes of read pairs rather than building the single-end bimodal shifting model.

Note--nomodel is not the same as --nolambda

--nomodel tells MACS3 to bypass the single-end shifting model and normally goes together with a user-specified --extsize (and, when appropriate, --shift). It is mainly relevant when analysing reads as single-end tags.

For this workshop we use -f BAMPE, so the paired-end fragment coordinates are already known and adding --nomodel is unnecessary.

--nolambda, discussed below, is completely different: it changes how MACS3 estimates the background used for the Poisson test.

MACS3 derives q-values from the genome-wide p-value distribution using the Benjamini-Hochberg procedure. The final narrowPeak interval is therefore a model-derived enriched region, not a directly observed object.

5.2 Where does the background lambda come from?

The central statistical comparison is between the observed treatment pileup, \(k(x)\), and an expected background, \(\lambda(x)\):

\[ X \sim Poisson(\lambda(x)) \]

MACS3 asks how surprising the observed pileup is under that background model. A large treatment pileup relative to \(\lambda(x)\) produces a small p-value.

The important point is that the source of \(\lambda\) changes depending on whether an external control is supplied.

Case 1: a control is supplied with -c

With an input, mock-IP or other control library, the treatment and control have different roles:

ChIP BAM ------------------------------> observed pileup k(x)

Control BAM
   |-- whole-genome background   lambda_BG
   |-- fragment-scale background lambda_d
   |-- 1 kb local background     lambda_slocal
   `-- 10 kb local background    lambda_llocal
                         |
                         v
                  lambda_local(x)

The genome-wide component is approximately:

\[ \lambda_{BG} = \frac{N_{control}\,d}{G_{effective}} \]

where \(N_{control}\) is the number of usable control reads/fragments, \(d\) is the characteristic fragment length and \(G_{effective}\) is the effective genome size.

MACS3 then estimates control-derived background at several spatial scales. By default these are approximately:

  • fragment scale, \(\lambda_d\);
  • small local window, \(\lambda_{slocal}\), controlled by --slocal, default 1000 bp;
  • large local window, \(\lambda_{llocal}\), controlled by --llocal, default 10000 bp;
  • the genome-wide baseline, \(\lambda_{BG}\).

At each genomic position, the standard local background is the most conservative of these estimates:

\[ \lambda_{local}(x) = \max\left(\lambda_{BG},\lambda_d(x),\lambda_{slocal}(x),\lambda_{llocal}(x)\right) \]

The 1 kb and 10 kb windows therefore estimate background around a genomic position. They are not the windows that define the final peak boundaries.

Before treatment and control are compared, MACS3 puts the two libraries on a comparable sequencing-depth scale. By default (--scale-to small), the larger library is scaled down to the depth of the smaller library.

NotePaired-end treatment versus control background

With -f BAMPE, MACS3 uses the observed paired-end fragments directly for the treatment pileup. The average insertion length \(d\) is still used when constructing the expected background scale. This distinction is one reason why \(d\) remains relevant even though paired-end fragments themselves do not need to be inferred from strand shifts.

Case 2: no control is supplied

Without -c, there is no independent negative library. MACS3 can still call peaks by deriving the background from the treatment library itself:

ChIP BAM
   |-------------------------------> observed pileup k(x)
   |
   `-- also provides information for the background model

The approximate genome-wide component now comes from the treatment depth:

\[ \lambda_{BG} = \frac{N_{ChIP}\,d}{G_{effective}} \]

If local-lambda modelling is left enabled, MACS3 can also derive local bias from the treatment data. This is mathematically possible, but it is not equivalent to having an independent control: the same library contains both the biological enrichment that we are trying to detect and the information being used to estimate local background.

Why MACS3 recommends --nolambda when no control is available

The current MACS3 documentation notes that --nolambda is particularly recommended when calling peaks without a control sample. With this option, MACS3 does not use the local 1 kb / 10 kb / fragment-scale bias around candidate peaks. Instead, it uses the background lambda as the local lambda:

\[ \lambda_{local}(x) = \lambda_{BG} \]

Conceptually:

NO CONTROL, local lambda enabled
ChIP -> treatment pileup
  `--> treatment-derived local background

NO CONTROL + --nolambda
ChIP -> treatment pileup
  `--> genome-wide background lambda_BG

This avoids allowing a strong treatment enrichment to contribute to a local background estimate around the same candidate peak. The trade-off is that without a control MACS3 cannot model locus-specific experimental biases that an independent input or negative-control library could reveal.

ImportantWorkshop choice

For the primary no-input analysis in Section 5.4, we do not supply an external -c control, so we use --nolambda. The statistical comparison in that route is therefore:

observed ChIP pileup k(x)
          versus
genome-wide background lambda_BG

This is a transparent no-control teaching analysis, but it is not equivalent to a control-based ChIP-seq experiment. Peak interpretation therefore relies heavily on replicate reproducibility, signal correlation, FRiP, bigWig inspection and biological validation.

The detailed behaviour of these options is described in the MACS3 callpeak documentation and its step-by-step peak-calling explanation.

5.3 Where an input or negative control belongs

A control is supplied at the MACS3 peak-calling step with -c, but choosing the control is first an experimental-design decision: which sources of background do we want the control to represent?

Design What it contributes Important limitation
matched input DNA fragmentation, mappability, copy-number and general sequencing background before immunoprecipitation it does not pass through antibody binding, beads, washes or immunoprecipitation
mock-IP or IgG ChIP background generated by the immunoprecipitation procedure a different antibody can have different affinity and nonspecific-binding behaviour
target-negative ChIP, such as an isogenic knockout or deletion the same antibody and ChIP procedure in material lacking the intended target deleting the target can alter physiology, chromatin or DNA accessibility
no external control MACS3 can derive background from the treatment; in this workshop --nolambda restricts this to the genome-wide background \(\lambda_{BG}\) no locus-specific experimental background is measured, and antibody/IP-specific artefacts are not represented

Equal read depth does not mean equal background information

Input and ChIP libraries are often sequenced to a similar total depth, but they contain very different fragment distributions:

input DNA = fragments distributed broadly across the genome
ChIP DNA  = fragments concentrated at enriched loci

An input with the same number of mapped fragments as the ChIP library can therefore still be relatively sparse at any particular locus. MACS3 can scale treatment and control libraries to comparable effective depths, but scaling cannot create local observations that were never sequenced. A shallow input can consequently become the limiting library; the presence of an input file does not automatically guarantee a better local background estimate.

This does not make input useless. A sufficiently informative input is valuable for pre-IP biases such as uneven fragmentation, mappability and copy-number effects. The point is that input depth should be chosen for the background it must estimate, rather than automatically matched one-for-one to the IP depth.

Input-free calling is not background-free calling

When no external control is supplied, peak calling still requires a null/background expectation. In our workshop that expectation is the treatment-depth-derived genome-wide \(\lambda_{BG}\) because --nolambda disables the additional treatment-derived local-bias terms. Independent QC therefore becomes especially important:

  • mapping quality and library complexity;
  • strand cross-correlation;
  • pairwise peak reproducibility with IDR;
  • replicate signal correlation across genomic bins;
  • fraction of usable fragments in called peaks (FRiP);
  • sample-level structure of the common peak-count matrix;
  • bigWig peak shape and signal-to-noise;
  • recovery of plausible sequence motifs;
  • consistency with the biological experiment.
NoteFG personal point of view

For a target-specific ChIP experiment, a well-matched target-negative ChIP can be more informative than input DNA for distinguishing genuine target-dependent enrichment from antibody- and IP-dependent background, because it passes through the complete immunoprecipitation procedure.

The publication used ΔHP1021 material as a target-negative ChIP control for confirmatory analysis. This is not the same as input DNA, and it is not a perfect control: deleting the target can change the biological state. In a complete experiment, input and target-negative ChIP can be complementary.

The workshop retains this exploratory no-input analysis for the core workflow. Section 5.5 adds a separate, optional WT-versus-ΔHP1021 negative-control peak-calling route. The two sets of calls should be interpreted with cross-correlation, replicate agreement, bigWig shape, motif evidence and biological context rather than treated as interchangeable.

6.1 IDR: reproducibility of ranked peak calls

After peak calling, one key question is whether biological replicates recover a consistent ranked set of enriched regions. We use Irreproducible Discovery Rate (IDR) as the formal replicate-level peak reproducibility framework.

A simple first check is the number of peaks called in each sample:

wc -l results/day3_chipseq/peaks/no_input/*_peaks.narrowPeak

Peak counts alone are not enough: two samples can contain similar numbers of peaks but disagree strongly about which regions are strongest. IDR therefore uses the relative ranking of matched peaks between two replicate peak lists.

IDR concept

We use the idr implementation distributed through Bioconda/Biocontainers:

quay.io/biocontainers/idr:2.0.4.2--py39h031d066_12

The statistical framework was introduced by Li, Brown, Huang and Bickel (2011), Measuring reproducibility of high-throughput experiments.

An interval overlap asks only:

Do two peak intervals intersect?

IDR asks a stronger question:

After matching peaks between replicates, are strong peaks strong in both replicates, and where does that rank agreement begin to break down?

Conceptually, IDR does four things:

  1. matches overlapping peaks between the two replicate lists;
  2. ranks the matched peaks using a chosen peak score;
  3. fits a two-component model containing a reproducible and an irreproducible component;
  4. assigns local and global measures of irreproducibility.

A useful interpretation is:

local IDR  ~ probability that one matched peak pair belongs to the irreproducible component

global IDR ~ cumulative irreproducibility among peaks at least this reproducible

IDR is therefore a rank-reproducibility analysis, not a differential-binding test and not simply an overlap percentage.

In this workshop we rank the MACS3 narrowPeak lists by p.value and use a global IDR threshold of 0.05. For narrowPeak, p.value refers to the -log10(p-value) score in column 8.

ImportantWhat is simplified here?

A formal production IDR workflow is usually built from long, relaxed or near-unthresholded ranked peak lists so that the model can see both the reproducible signal and the weaker tail. To keep this workshop linear, we deliberately reuse the same MACS3 peak list produced by the single callpeak command.

This is sufficient to teach pairwise rank reproducibility, but it can make IDR less informative if the MACS3 output contains only strong peaks. We also stop short of a full ENCODE-style IDR workflow: we do not add pooled-replicate or pseudo-replicate analyses.

6.2 Replicate signal correlation with deepTools

IDR compares peak lists. We also want a peak-independent view of whether biological replicates have similar ChIP-seq signal across the genome. A standard approach is to summarize each BAM over the same genomic bins and correlate the resulting vectors.

  • --samFlagInclude 64 keeps one representative record per pair, avoiding counting the same fragment twice;
  • Spearman correlation compares the ordering of genomic-bin signal and is less dominated by a few extreme bins than Pearson correlation.

6.3 FRiP: fraction of usable fragments in called peaks

The fraction of reads in peaks (FRiP) is a simple ChIP-seq signal-to-noise metric:

\[ \mathrm{FRiP} = \frac{\text{usable fragments overlapping called peaks}}{\text{all usable fragments}} \]

Here, “usable” means the fragments represented in the filtered BAMs from Section 3. Because our data are paired-end, we count each physical pair once using --samFlagInclude 64 and extend that representative record to the full mate-defined fragment with --extendReads.

NoteWorkshop definition of usable fragments

The filtered BAMs retain duplicate-marked alignments in this workshop, so the FRiP value calculated here also retains them. This keeps the metric consistent with the BAMs used for peak calling and visualization. Other production pipelines may define “usable fragments” differently, for example after duplicate removal; FRiP values should therefore only be compared when the upstream filtering and peak-calling rules are comparable.

We calculate FRiP against each sample’s own MACS3 peaks. The same MACS3 command and default significance rule were used for every sample, which makes within-workshop comparisons interpretable. FRiP depends strongly on how peaks were called: more numerous, broader or more permissive peaks generally increase FRiP.

We use deepTools plotEnrichment, which directly reports the percentage and the underlying fragment counts.

7. Build one common peak set and count matrix

For downstream sample comparison, every sample must be measured over the same genomic intervals. For the core DESeq2 exercise we compare WT_1–WT_3 versus WTS_1–WTS_3; ΔHP1021 libraries are negative-control candidates for the optional MACS3 route, not part of the WT treatment-effect design. Explicitly selecting these six samples also avoids accidentally importing ΔHP1021 BAMs into the WT/WTS count matrix.

We use a deliberately transparent rule:

  1. MACS3 has already produced one peak list per sample;
  2. filter each narrowPeak on column 9, the -log10(q-value) score, using a configurable minimum;
  3. concatenate retained peaks from the six WT/WTS no-input calls and sort by chromosome and start coordinate;
  4. merge overlapping or book-ended intervals with bedtools merge;
  5. count the six WT/WTS BAM libraries over every merged interval with bedtools multicov.

Here, “consensus” means a union of peaks passing a stringent significance threshold. It does not mean “present in every replicate”, and it is not the IDR-thresholded peak set. The filter works on MACS3 narrowPeak column 9: a score of 10 means q ≤ 1e-10, while a score of 15 means q ≤ 1e-15. The default below is 15; change one variable to test another cutoff. A peak in just one sample can still enter this union, so use IDR or an explicit replicate-support rule for reproducibility.

9. Differential peak occupancy with DESeq2

We now test whether the raw count for a common genomic interval differs systematically between control and stressed samples.

The logic is directly analogous to Day 2 RNA-seq:

raw peak counts
  -> sample design
  -> DESeq2 normalization + dispersion estimation
  -> negative-binomial model
  -> stressed versus control
  -> adjusted p-values

The numbers 1, 2, and 3 in the sample names are independent biological replicate identifiers, not matched blocks. Therefore the model is:

design = ~ conditions

11. De novo motif discovery with STREME

ChIP-seq tells us where a protein-associated enrichment occurs in the genome. Motif analysis asks a different question:

Do those enriched regions share a short DNA sequence pattern more often than expected by chance?

A motif is not one exact sequence. It is a probabilistic description of a family of related sequences. For example, a protein may strongly prefer ACGTG, but tolerate different nucleotides at some positions. A motif therefore describes, position by position, which bases are preferred and how strongly.

We use STREME from the MEME Suite for de novo motif discovery.

De novo means that we do not give STREME a known HP1021 binding motif and ask whether it is present. Instead, STREME starts from the peak sequences themselves and searches for recurring patterns that are enriched compared with a background set.

This makes motif discovery useful when:

  • the DNA-binding preference is unknown;
  • we want to recover the expected motif without forcing the answer;
  • we want to detect additional motifs that could reflect cofactors or other sequence features associated with the peaks.

11.1 What STREME is comparing

STREME is a discriminative motif finder. It compares two groups of sequences:

primary sequences   = DNA from our ChIP-seq peaks
control sequences   = DNA representing the expected background

The question is therefore not simply:

Which short sequence occurs many times?

It is:

Which short sequence pattern occurs more often in the peak sequences than in an appropriate background?

In this workshop we provide only the peak FASTA. STREME therefore creates the control set automatically by shuffling each primary sequence. With the default DNA settings used here, the shuffling preserves short-word composition, including 3-mer frequencies, and STREME uses a corresponding order-2 Markov background model.

This matters because bacterial DNA is not compositionally random. Some short words are common simply because of GC content or local sequence composition. A composition-matched background makes it less likely that STREME reports such generic sequence properties as a biologically interesting motif.

11.2 From recurring words to a motif model

STREME does not test only one exact DNA word. Conceptually, it proceeds from candidate sequence words toward a more flexible motif representation:

  1. Find promising seed words. Short words enriched in the primary sequences relative to the controls provide starting points.
  2. Refine the motif. Similar sequence occurrences are collected and used to improve the model.
  3. Represent the motif as a position-weight matrix (PWM). Each position stores the preference for A, C, G and T rather than requiring one exact sequence.
  4. Search both DNA strands. A DNA-binding site may occur in either orientation, so the reverse complement is considered automatically for DNA.
  5. Evaluate enrichment. STREME asks whether sequences containing good matches to the motif are more frequent in the primary set than in the control set.
  6. Continue searching. After a motif is found, its strongest sites are masked/erased and STREME can search for additional motifs in the remaining sequence information.

The familiar sequence logo is simply a graphical representation of the PWM. Positions with a strong base preference appear more constrained; positions where several bases are tolerated appear less specific.

NoteA motif is a model, not a consensus string

A consensus such as ACGTG is a convenient summary, but the PWM contains more information. Two sites can both match the same motif even when their sequences are not identical.

11.3 How STREME assesses significance

Finding a pattern in the same sequences used to discover it would make significance look artificially strong. STREME therefore separates motif discovery from motif evaluation.

With enough input sequences, it keeps aside a hold-out subset of the primary and control sequences. The motif is learned using the remaining sequences and then evaluated on the held-out sequences that were not used to optimize it.

For primary and control sets with comparable sequence-length distributions, enrichment is typically evaluated using Fisher’s exact test. If the sequence-length distributions differ, STREME can use a different test such as the binomial test.

The output can contain several related quantities:

Quantity Interpretation
motif score how well the motif discriminates the training sequences; not by itself a final significance measure
p-value enrichment significance evaluated on the hold-out set when enough sequences are available
E-value p-value adjusted for the number of motifs reported; use this when comparing the significance of multiple reported motifs
primary / control matches how many sequences in each set contain a match above the selected motif threshold
WarningSmall peak sets need cautious interpretation

STREME needs enough sequences to reserve an independent hold-out set. With a small ChIP-seq peak set, it may report a score rather than a reliable motif p-value, or may not provide an E-value. In that situation, do not treat the numerical score as formal evidence of statistical significance. Inspect the motif, the number of supporting peak sequences, its positional behaviour and the underlying ChIP-seq evidence together.

11.4 What a motif can and cannot tell us

For a DNA-binding protein, recovery of a clear enriched motif can strengthen the interpretation that at least a subset of peaks represent sequence-specific binding. However, motif discovery does not prove that every ChIP-seq peak is a direct binding event.

A motif found in ChIP-seq peaks could represent:

  • the direct DNA-recognition sequence of the immunoprecipitated protein;
  • a motif associated with another protein or cofactor;
  • a sequence feature correlated with the genomic regions being enriched;
  • a pattern introduced or exaggerated by how the peak sequences and background were defined.

Likewise, failure to find a strong motif does not automatically mean that the ChIP-seq experiment failed. Binding may be weakly sequence-specific, indirect, dependent on cofactors, or represented by too few peaks for robust motif discovery.

ImportantWorkshop simplification

Here we extract the entire merged peak intervals because this connects directly to the common BED object used earlier in the workshop.

For a research-grade motif analysis, it is often preferable to use a consistent window around a high-confidence peak summit, for example a fixed-width region centred on each summit. This prevents very broad or merged intervals from contributing large amounts of unrelated flanking sequence and usually gives the motif finder a more focused representation of the likely binding site.

The teaching question for this workshop is therefore:

Is there a recurring DNA pattern enriched in our merged ChIP-seq peak sequences relative to composition-matched shuffled versions of those same sequences?

11.7 Read the STREME report

Open streme.html. Do not stop at the sequence logo. For each reported motif, ask:

  • How many primary peak sequences contain the motif? A striking logo supported by only a handful of peaks should be interpreted cautiously.
  • How often is it found in the control sequences? The relevant signal is enrichment in primary versus control sequences, not raw occurrence alone.
  • What is the motif width and information content? Is the pattern specific enough to be biologically meaningful?
  • What significance quantity is reported? Prefer the E-value when STREME reports multiple motifs; if only a score is available because the dataset is small, do not interpret it as a formal p-value.
  • Where do the motif matches occur within the peak sequences? For direct ChIP-seq binding, enrichment near peak centres or summits can provide useful supporting evidence, although our merged-peak representation makes this less precise than a summit-centred analysis.
  • Is the motif present in many peaks or only a subset? A subset can still be biologically meaningful and may indicate multiple binding modes or indirect peaks.
  • Does the motif make biological sense for HP1021? Motif discovery should be interpreted together with prior biological knowledge, not instead of it.
  • Would a different background change the result? A matched genomic background or target-negative peak set could answer a different and potentially stronger biological question than shuffled sequences.

The final interpretation should combine several independent pieces of evidence:

ChIP enrichment
+ replicate agreement
+ peak shape
+ motif enrichment
+ biological context
----------------------------
stronger support for a real binding model

A motif is therefore supporting evidence for a binding mechanism, not an automatic annotation of every ChIP-seq peak as a direct binding site.
