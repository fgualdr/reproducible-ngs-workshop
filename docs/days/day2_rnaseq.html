3. Reference-based RNA-seq FASTQ mapping

RNA-seq mapping asks where each sequenced read, or read pair, fits on a reference sequence. The input is FASTQ. The output is an alignment file that records the genomic position and alignment details for each read.

Mapping starts from:

  • trimmed FASTQ files from Day 1;
  • a reference genome FASTA;
  • an aligner index built from that FASTA.

The index does not change the genome. It creates extra files that allow the aligner to search the genome quickly.

3.1 Alignment versus pseudoalignment

Full aligners try to place each read or read pair at one or more genomic or transcriptomic coordinates. A common strategy is seed-and-extend:

  1. split or sample short exact pieces of the read called seeds;
  2. use the index to find candidate reference positions for those seeds;
  3. extend candidate alignments across the full read;
  4. score each alignment using matches, mismatches, gaps, clipping, base qualities, and sometimes paired-end consistency;
  5. report the best alignment or alignments, usually with a mapping quality score.

The exact scoring system differs by tool. In general, a better score means the read agrees better with the reference. If several locations have similar scores, the read is ambiguous and the mapping quality is lower. For paired-end reads, aligners also use whether both mates map with the expected orientation and distance.

Splice-aware RNA-seq aligners add another idea: a read may align across two exons with a skipped intron between them. These aligners can represent exon-exon junctions in the alignment. This is essential for many eukaryotic RNA-seq datasets but unnecessary for this bacterial workshop.

Pseudoaligners and quasi-aligners usually do not try to report one exact genomic coordinate for every read. Instead, they infer which transcript or set of transcripts is compatible with each read or fragment. This is very fast and useful for transcript quantification, but it is a different workflow from creating genome-coordinate BAM files for IGV and feature counting.

3.2 SAM and BAM files

The general alignment file created by an aligner is SAM:

Sequence Alignment/Map format

SAM is a plain-text alignment format. BAM is the compressed binary version of SAM. In practice, we usually create a temporary SAM file, convert it to BAM, sort the BAM by genomic coordinate, and create a BAM index file:

sample.sam
  -> sample.sorted.bam
  -> sample.sorted.bam.bai

The sorted BAM is compact and fast for downstream tools. The .bai index lets software jump directly to one genomic region without reading the whole BAM file.

A BAM file contains one alignment record per read alignment. The common SAM/BAM fields are:

Field Meaning
QNAME Read name from the FASTQ identifier
FLAG Bit-coded alignment status, such as paired, mapped, reverse strand, secondary, supplementary, duplicate
RNAME Reference sequence name, such as chromosome or contig
POS 1-based leftmost alignment coordinate
MAPQ Mapping quality, a score for confidence in the reported position
CIGAR Compact description of matches, insertions, deletions, clipping, and skipped reference regions
RNEXT Reference name for the mate read in paired-end data
PNEXT Position of the mate read
TLEN Template length inferred from the read pair
SEQ Read sequence
QUAL Base quality string

The CIGAR string is important for RNA-seq. In bacterial RNA-seq, reads usually align continuously because bacterial genes usually do not contain spliceosomal introns. In eukaryotic RNA-seq, a read can span an exon-exon junction. Splice-aware aligners represent this with an N operation in the CIGAR string, meaning a skipped region in the reference. Other CIGAR operations include M for aligned match/mismatch, I for insertion relative to the reference, D for deletion relative to the reference, and S for soft clipping.

Aligners also write optional tags after the common columns. These tags are tool-specific. Common examples include edit distance, alignment score, number of possible alignments, or strand information. This is one reason BAM files from different aligners can contain the same core information but different additional descriptors.

3.3 How paired-end reads are stored in BAM

Paired-end FASTQ files have one R1 file and one R2 file. In the BAM file, the two ends are not stored as one combined row. They are stored as two separate alignment records with the same read name (QNAME), one record for read 1 and one record for read 2.

The pair relationship is encoded in the BAM fields:

BAM field Paired-end meaning
QNAME Same read-pair identifier for R1 and R2
FLAG Says whether this record is read 1 or read 2, whether the mate is mapped, whether the pair is properly paired, and which strand each end maps to
RNAME and POS Reference name and position for this read end
RNEXT and PNEXT Reference name and position for the mate read
TLEN Inferred template length, meaning the genomic span covered by the read pair
CIGAR Alignment shape for this read end only

For a simple properly paired fragment, R1 and R2 usually map to nearby positions on opposite strands with an expected orientation. The two BAM records point to each other through the mate fields. When we sort a BAM by coordinate, the two mates may no longer be next to each other in the file, but the mate information remains encoded in the records.

This is why paired-end tools can count fragments rather than individual read ends. Later, featureCounts uses the paired-end information to assign one fragment-level count to a gene instead of counting R1 and R2 separately.

3.4 Build the Bowtie2 index

Bowtie2 must search for possible locations for millions of reads. Searching the FASTA sequence from beginning to end for every read would be inefficient, so bowtie2-build converts the reference genome into compact index files that Bowtie2 can search quickly. We build the index once for this exact genome and reuse it for every RNA-seq and ChIP-seq sample; if the reference FASTA changes, the index must be rebuilt.

This reference-genome index is different from the .bai index described above: the Bowtie2 index makes the genome searchable before alignment, whereas a .bai file makes an aligned BAM searchable by genomic position afterward.

3.5 Map RNA-seq reads

The mapping script uses the Day 1 trimmed RNA-seq FASTQ files. It writes Bowtie2 logs, sorted BAM files, BAM indexes, and samtools mapping summaries.

Create scripts/day2_rnaseq/02_map_bowtie2_sort_index.sh:

nano scripts/day2_rnaseq/02_map_bowtie2_sort_index.sh

Paste this script:

#!/usr/bin/env bash
set -euo pipefail

fastq_dir="results/day1_qc/trimmed_fastq/rnaseq"
index_prefix="reference_genome/bowtie2_index/genome"
bam_dir="results/day2_rnaseq/bam"
log_dir="results/logs/day2"

mkdir -p "${bam_dir}" "${log_dir}"

for read1 in "${fastq_dir}"/*_R1.trimmed.fastq.gz
do
  [[ -e "${read1}" ]] || continue

  read2="${read1/_R1.trimmed.fastq.gz/_R2.trimmed.fastq.gz}"
  sample_id="$(basename "${read1}" _R1.trimmed.fastq.gz)"
  sam_file="${bam_dir}/${sample_id}.sam"
  bam_file="${bam_dir}/${sample_id}.sorted.bam"
  filtered_bam="${bam_dir}/${sample_id}.filtered.bam"

  if [[ ! -f "${read2}" ]]; then
    echo "ERROR: paired read not found for ${read1}" >&2
    exit 1
  fi

  echo "Mapping ${sample_id}"
  bowtie2 \
    -x "${index_prefix}" \
    -1 "${read1}" \
    -2 "${read2}" \
    -p 2 \
    -S "${sam_file}" \
    2> "${log_dir}/${sample_id}.bowtie2.log"

  # Convert the SAM alignments to a coordinate-sorted BAM.
  # samtools sort accepts SAM input directly; -O BAM makes the output format explicit.
  samtools sort \
    -@ 2 \
    -O BAM \
    -o "${bam_file}" \
    "${sam_file}"

  samtools index "${bam_file}"

  samtools flagstat "${bam_file}" > "${log_dir}/${sample_id}.flagstat.txt"

  samtools view \
    -@ 2 \
    -b \
    -q 10 \
    -f 2 \
    -F 2828 \
    -o "${filtered_bam}" \
    "${bam_file}"

  samtools index "${filtered_bam}"

  samtools flagstat "${filtered_bam}" > "${log_dir}/${sample_id}.filtered.flagstat.txt"

  rm -f "${sam_file}"
done

The loop performs the following steps for each paired-end sample.

trimmed R1 + R2
  -> Bowtie2 mapping -> temporary SAM + Bowtie2 log
  -> samtools sort -> coordinate-sorted BAM
  -> samtools index + flagstat
  -> samtools view filtering -> filtered BAM
  -> samtools index + flagstat
  -> remove temporary SAM

3.5.1 Map the paired reads

bowtie2 uses the Bowtie2 index (-x) and the trimmed R1/R2 files (-1 and -2) to find genomic alignments. It writes:

  • a temporary SAM file containing the alignments;
  • a Bowtie2 log containing the alignment summary.

The log is written separately with 2> because Bowtie2 sends its progress and summary information to the standard-error stream.

3.5.2 Convert SAM to a coordinate-sorted BAM

samtools sort reads the text SAM file directly and writes a coordinate-sorted BAM. The -O BAM option makes the output format explicit:

samtools sort \
  -@ 2 \
  -O BAM \
  -o "${bam_file}" \
  "${sam_file}"

Conversion and sorting therefore happen in the same command. Coordinate sorting places alignments from the same genomic region together, which is required for BAM indexing and makes downstream access efficient.

3.5.3 Index and summarize the sorted BAM

samtools index creates sample.sorted.bam.bai. This index allows programs to jump directly to one genomic region without reading the complete BAM.

samtools flagstat then creates the first mapping summary. It reports totals such as mapped reads and properly paired reads before we apply alignment filters.

3.5.4 Filter alignments for counting

The script creates a second BAM containing the alignments we want to use for gene counting:

samtools view \
  -@ 2 \
  -b \
  -q 10 \
  -f 2 \
  -F 2828 \
  -o "${filtered_bam}" \
  "${bam_file}"
Option Meaning
-b Write BAM output
-q 10 Keep alignments with mapping quality of at least 10
-f 2 Require the read to belong to a properly aligned pair
-F 2828 Exclude unmapped reads, reads whose mate is unmapped, secondary alignments, failed-QC reads, and supplementary alignments

SAM flags are bit-coded and do not need to be memorized. The Picard flag converter can be used to inspect a filter.

We do not exclude reads marked as duplicates in this workshop RNA-seq workflow. Multiple reads at the same position can represent high gene expression rather than PCR duplication, so removing them can bias counts.

3.5.5 Index and summarize the filtered BAM

The filtered BAM is also indexed and summarized with samtools flagstat. Comparing the summaries before and after filtering shows how many alignments were removed. Finally, the temporary SAM is deleted because the sorted BAM contains the alignment information in a smaller, more useful form.

3.6 RNA-seq-specific alignment QC: duplication, multi-mapping and residual rRNA

The mapping workflow in Section 3.5 produces *.sorted.bam files containing the alignments before our standard filtering and *.filtered.bam files used for downstream gene counting.

Keep the standard workshop filtering unchanged.

Here we use the unfiltered alignments to investigate three additional RNA-seq-specific QC properties:

  1. duplication — does duplication depend on transcript abundance, and what fraction of alignments share coordinates?
  2. multi-mapping — how many reads or read pairs have more than one plausible genomic placement?
  3. residual rRNA — how much of the sequenced library derives from ribosomal RNA?

These are first QC measurements. Whether reads should subsequently be removed depends on the biological question and on how the aligner represents alignment ambiguity.

We perform the QC using:

docker.io/fgualdr/ngs-dupradar:latest

which provides samtools, featureCounts, R/Bioconductor and dupRadar.

3.6.1 Duplication: measure it, but do not automatically remove it

RNA-seq duplication cannot be interpreted in the same way as duplication in genomic DNA sequencing.

Highly expressed transcripts naturally generate many fragments from the same genomic regions. RNA fragmentation also does not guarantee completely random start and end coordinates. Consequently, two independently sampled RNA molecules can generate reads with identical alignment coordinates.

Without unique molecular identifiers (UMIs), coordinate identity alone cannot reliably distinguish:

  • PCR duplicates;
  • independently sampled molecules from an abundant transcript.

We therefore assess duplication in two complementary ways:

  • samtools markdup provides the overall coordinate-duplicate fraction;
  • dupRadar evaluates whether duplication depends on gene expression.

We mark duplicates for QC but do not remove them.

Create:

nano scripts/day2_rnaseq/02_rnaseq_alignment_qc.sh

Add:

#!/usr/bin/env bash
set -euo pipefail

bam_dir="results/day2_rnaseq/bam"
log_dir="results/logs/day2"
qc_dir="results/day2_rnaseq/qc"
annotation="reference_genome/annotation.gff3"

mkdir -p "${qc_dir}/marked" "${qc_dir}/tmp"

# ------------------------------------------------------------
# Prepare gene-level GTF for dupRadar
# ------------------------------------------------------------

awk 'BEGIN{FS=OFS="\t"}
!/^#/ && $3=="gene" {
    id=""
    n=split($9,a,";")

    for(i=1;i<=n;i++) {
        if(a[i] ~ /^ID=/) {
            id=substr(a[i],4)
            break
        }
    }

    if(id!="") {
        $3="exon"
        $9="gene_id \"" id "\"; transcript_id \"" id "\";"
        print
    }
}' "${annotation}" > "${qc_dir}/dupradar_genes.gtf"

[[ -s "${qc_dir}/dupradar_genes.gtf" ]] || {
    echo "No gene features found in ${annotation}" >&2
    exit 1
}

# ------------------------------------------------------------
# Prepare rRNA-only annotation
# ------------------------------------------------------------

awk 'BEGIN{FS=OFS="\t"}
!/^#/ && $3=="rRNA" {print}
' "${annotation}" > "${qc_dir}/rrna.gff3"

[[ -s "${qc_dir}/rrna.gff3" ]] || {
    echo "No rRNA features found in ${annotation}" >&2
    exit 1
}

# ------------------------------------------------------------
# Coordinate-duplicate summary
# ------------------------------------------------------------

printf "sample\tprimary_mapped\tduplicates\tduplicate_percent\n" \
    > "${qc_dir}/coordinate_duplicates.tsv"

for bam in "${bam_dir}"/*.sorted.bam; do

    [[ -e "${bam}" ]] || continue

    sample="$(basename "${bam}" .sorted.bam)"

    echo "Duplicate QC: ${sample}"

    samtools sort -n -@ 2 \
        -o "${qc_dir}/tmp/${sample}.name.bam" \
        "${bam}"

    samtools fixmate -m \
        "${qc_dir}/tmp/${sample}.name.bam" \
        "${qc_dir}/tmp/${sample}.fixmate.bam"

    samtools sort -@ 2 \
        -o "${qc_dir}/tmp/${sample}.position.bam" \
        "${qc_dir}/tmp/${sample}.fixmate.bam"

    samtools markdup \
        "${qc_dir}/tmp/${sample}.position.bam" \
        "${qc_dir}/marked/${sample}.marked.bam"

    samtools index \
        "${qc_dir}/marked/${sample}.marked.bam"

    # 2308 = unmapped (4) + secondary (256) + supplementary (2048)
    total=$(samtools view -c -F 2308 \
        "${qc_dir}/marked/${sample}.marked.bam")

    duplicates=$(samtools view -c -f 1024 -F 2308 \
        "${qc_dir}/marked/${sample}.marked.bam")

    awk \
        -v s="${sample}" \
        -v n="${total}" \
        -v d="${duplicates}" \
        'BEGIN {
            printf "%s\t%d\t%d\t%.2f\n",
                   s,n,d,(n>0 ? 100*d/n : 0)
        }' >> "${qc_dir}/coordinate_duplicates.tsv"

done

# ------------------------------------------------------------
# Residual rRNA
# ------------------------------------------------------------

featureCounts \
    -T 2 \
    -p \
    --countReadPairs \
    -s 0 \
    -t rRNA \
    -g ID \
    -a "${qc_dir}/rrna.gff3" \
    -o "${qc_dir}/rrna_counts.txt" \
    "${bam_dir}"/*.sorted.bam

rm -rf "${qc_dir}/tmp"

echo
echo "Coordinate duplication:"
column -t "${qc_dir}/coordinate_duplicates.tsv"

echo
echo "RNA-seq alignment QC completed."

3.6.2 Expression-dependent duplication with dupRadar

The global duplicate percentage does not tell us whether duplication is concentrated among highly expressed genes.

dupRadar relates duplication rate to expression level and is therefore more informative for RNA-seq. Because this QC section comes before the empirical strandedness check in Section 3.7, we run the duplication and rRNA-assignment diagnostics unstranded. The final gene-counting step later uses the empirically supported -s 2 setting.

nano scripts/day2_rnaseq/02_dupradar.R

Add:

library(dupRadar)

qc_dir <- "results/day2_rnaseq/qc"
gtf <- file.path(qc_dir, "dupradar_genes.gtf")

3.6.3 Multi-mapping: alignment scores, MAPQ and filtering

A read is considered a multi-mapper when it can align to more than one genomic position.

However, not all alternative alignments are equally plausible. A read may have one very good alignment and several substantially worse alternatives.

The central question is therefore not simply:

Can this read align somewhere else?

Instead, we ask:

How confident are we that the reported alignment represents the correct genomic origin?

Three kinds of information help us answer this:

  • Alignment score (AS) measures how well a sequence aligns to a particular genomic location.
  • Alternative alignment information indicates whether other plausible genomic placements exist.
  • Mapping quality (MAPQ) summarizes the aligner’s confidence in the reported placement.

MAPQ is reported in column 5 of a SAM file.

For ordinary gene-level RNA-seq, filtering on mapping confidence is generally preferable to automatically removing every read for which an alternative alignment exists.

This distinction is particularly important for paired-end sequencing, where the two mates provide additional information about the fragment’s genomic origin.

Understanding SAM FLAGs

SAM FLAGs describe properties of an alignment record. They do not directly indicate how many genomic locations a read can map to.

FLAG Meaning
0x1 (1) Read belongs to a pair
0x2 (2) Properly paired alignment
0x4 (4) Read unmapped
0x8 (8) Mate unmapped
0x100 (256) Secondary alignment
0x200 (512) Failed vendor/platform QC
0x400 (1024) Duplicate
0x800 (2048) Supplementary alignment

The distinction between secondary and multimapping is essential.

A read with several possible genomic placements can still have one primary alignment. Removing secondary alignments therefore does not necessarily remove multimapping reads.

Similarly, the duplicate FLAG (0x400) describes coordinate duplication, not multimapping.

For paired-end RNA-seq, we generally want to retain both mates of a confidently aligned fragment.

Bowtie2: alignment scores and MAPQ

Bowtie2 is the aligner used in our workshop.

It reports the score of the selected alignment using:

AS:i:<score>

When another alignment was found, Bowtie2 can also report:

XS:i:<score>

This represents the score of the best alternative alignment found.

For example:

AS:i:-2
XS:i:-15

The reported alignment is substantially better than the alternative.

In contrast:

AS:i:-2
XS:i:-2

indicates that Bowtie2 found an alternative with an equally good score.

The second situation is more ambiguous because the alignment scores do not distinguish the two genomic locations.

However, the difference between AS and XS should not be used as a universal filtering threshold.

Bowtie2 already incorporates information about alternative alignments into its MAPQ calculation.

Importantly, Bowtie2 does not guarantee that every possible genomic placement has been discovered.

Therefore:

  • XS present means an alternative alignment was found.
  • XS absent does not prove that the read is uniquely mappable.
  • A larger AS–XS difference generally supports greater confidence.
  • MAPQ provides the practical alignment-confidence measure.

For paired-end data, Bowtie2 also evaluates concordance, orientation and fragment length when assessing the alignment of a read pair.

Inspecting multimapping

Bowtie2 reports:

aligned concordantly 1 time
aligned concordantly >1 times

We can inspect these categories in the mapping logs:

grep -E \
  "aligned concordantly 1 time|aligned concordantly >1 times" \
  results/logs/day2/*.bowtie2.log

These statistics describe concordantly aligned pairs and are useful for comparing samples.

Filtering Bowtie2 alignments

Our existing workshop workflow uses:

samtools view \
  -b \
  -q 10 \
  -f 2 \
  -F 2828 \
  -o sample.filtered.bam \
  sample.sorted.bam

The options mean:

Option Interpretation
-b Write BAM output
-q 10 Retain alignments with MAPQ ≥ 10
-f 2 Require the proper-pair FLAG
-F 2828 Exclude unmapped, mate-unmapped, secondary, QC-failed and supplementary records

The value 2828 corresponds to:

4 + 8 + 256 + 512 + 2048

We do not exclude duplicate reads (0x400).

The resulting BAM contains confidently aligned primary records from proper pairs.

This is a sensible default for the workshop, but it is important to understand that MAPQ ≥ 10 is not an absolute guarantee of unique mapping.

A higher MAPQ threshold can be used when greater confidence is required, at the cost of discarding more alignments.

For example:

samtools view \
  -b \
  -q 30 \
  -f 2 \
  -F 2828 \
  -o sample.mapq30.bam \
  sample.sorted.bam

samtools index sample.mapq30.bam

This is an optional sensitivity analysis, not a replacement for our standard filtering.

STAR: the NH tag and MAPQ

STAR reports multimapping information explicitly.

The optional SAM tag:

NH:i:1

indicates that STAR identified one genomic mapping location.

Conversely:

NH:i:3

indicates three genomic mapping locations.

Thus:

  • NH:i:1 identifies uniquely mapped reads according to STAR.
  • NH:i:N, with N > 1, identifies multimappers.

STAR also reports these categories in Log.final.out:

Uniquely mapped reads number
Uniquely mapped reads %
Number of reads mapped to multiple loci
% of reads mapped to multiple loci

Under STAR’s default settings, uniquely mapped reads receive:

MAPQ = 255

This differs from Bowtie2, where MAPQ values are calculated using a different scoring scheme.

Optional STAR filtering

With STAR’s default MAPQ convention, we can select uniquely mapped primary alignments using:

samtools view \
  -b \
  -q 255 \
  -f 2 \
  -F 2828 \
  -o sample.star.unique.bam \
  sample.star.sorted.bam

samtools index sample.star.unique.bam

This selects proper-pair alignments assigned STAR’s unique-mapping MAPQ category.

The approach assumes that STAR was run with its default --outSAMmapqUnique 255 setting.

An alternative is to select records explicitly carrying NH:i:1, which is particularly useful if STAR’s MAPQ convention was modified.

For example, with a samtools version supporting auxiliary-tag expressions:

samtools view \
  -b \
  -f 2 \
  -F 2828 \
  -e '[NH] == 1' \
  -o sample.star.unique.bam \
  sample.star.sorted.bam

This selects records for which STAR reports one mapping location.

HISAT2: NH, ZS and MAPQ

HISAT2 combines features of the Bowtie2 alignment framework with RNA-seq-specific spliced alignment.

Like STAR, HISAT2 can report:

NH:i:<N>

This indicates the number of mapped locations for the read or read pair.

HISAT2 also reports:

AS:i:<score>

for the alignment score, and:

ZS:i:<score>

for the score of the best alternative alignment found.

Note: HISAT2 uses ZS:i for alternative alignment scores, whereas Bowtie2 uses XS:i.

In HISAT2, XS:A:+ or XS:A:- instead describes transcript strand.

This is an important distinction because SAM optional tags are aligner-specific.

Optional HISAT2 filtering

If the BAM contains the NH tag, we can select uniquely mapped primary alignments using:

samtools view \
  -b \
  -f 2 \
  -F 2828 \
  -e '[NH] == 1' \
  -o sample.hisat2.unique.bam \
  sample.hisat2.sorted.bam

samtools index sample.hisat2.unique.bam

Alternatively, if our objective is to retain confidently mapped alignments rather than enforce strict uniqueness, we can filter by MAPQ:

samtools view \
  -b \
  -q 10 \
  -f 2 \
  -F 2828 \
  -o sample.hisat2.filtered.bam \
  sample.hisat2.sorted.bam

samtools index sample.hisat2.filtered.bam

These two approaches answer slightly different questions.

NH == 1 selects alignments for which HISAT2 reports one genomic placement.

MAPQ ≥ 10 selects alignments meeting a mapping-confidence threshold.

Neither criterion guarantees that all possible genomic placements were exhaustively discovered.

Paired-end filtering: an important consideration

Our RNA-seq libraries are paired-end.

A paired-end fragment consists of two reads, but BAM filtering operates on individual alignment records.

This distinction matters.

For example, when using:

samtools view -q 30

one mate might pass the threshold while the other does not.

The output can therefore contain only one mate of a fragment.

Similarly:

samtools view -f 2

requires the proper-pair FLAG, but does not guarantee that both mates survive an additional MAPQ or tag-based filter.

For gene-level paired-end counting, this can be undesirable.

If we require both mates to satisfy the filtering criterion, we must perform pair-aware filtering rather than assuming that samtools view automatically preserves complete pairs.

For our workshop, the existing filtering is retained for consistency with the mapping and counting exercises.

When designing a stricter analysis, the recommended procedure is to:

  1. Evaluate mapping confidence for both mates.
  2. Retain the fragment only when both mates satisfy the selected criteria.
  3. Preserve both records in the output BAM.
  4. Sort and index the resulting BAM.
  5. Verify the number of retained complete pairs before counting.

This is especially important when comparing different aligners or using strict uniqueness criteria.

Which filtering strategy should we use?
Aligner Alternative alignment information Explicit multiplicity tag Practical filtering
Bowtie2 XS:i No standard NH output MAPQ + FLAGs
STAR Multiple reported alignments NH:i NH == 1 or STAR-specific MAPQ
HISAT2 ZS:i NH:i NH == 1 or MAPQ + FLAGs

For conventional gene-level RNA-seq, our preferred default is confidence-based filtering rather than automatically discarding every read with an alternative alignment.

A read with one substantially better alignment can still provide useful information.

Conversely, a read with several equally good placements should generally have low mapping confidence.

However, MAPQ is an aligner-dependent estimate, and low MAPQ does not identify every possible multimapper perfectly.

For studies of repetitive elements, transposable elements or duplicated gene families, we may deliberately retain multimappers and use quantification methods designed to handle ambiguous placements.

Workshop decision: continue using the existing Bowtie2 *.filtered.bam files with MAPQ ≥ 10, retain coordinate duplicates, and treat stricter filtering as an optional sensitivity analysis.

Genes are transcribed from either the + or the - genomic strand. 5. From a count matrix to differential expression with DESeq2

The featureCounts table gives us one integer count per gene and sample. At this point the main question changes:

Are the differences we observe between conditions larger than we would expect from biological and sampling variability?

Before answering that question, we first need to understand what DESeq2 is, why it is commonly used, what assumptions it makes, and how the experimental design enters the analysis.

5.1 Why DESeq2?

There is no single differential-expression tool for RNA-seq. Widely used alternatives include edgeR, limma-voom, DSS, and others. In this workshop we use DESeq2 because it has become one of the de facto reference frameworks for bulk RNA-seq differential expression: it is widely used, well documented, supports simple and complex experimental designs, and links normalization, dispersion estimation, generalized linear models, statistical testing, diagnostics, and result extraction in one coherent workflow.

DESeq2 is an R/Bioconductor package. In everyday speech, R packages are often called libraries, although technically a package is the bundled collection of functions, classes, documentation, and supporting data, while library(DESeq2) loads that package into the current R session. DESeq2 is therefore not one single test: it is a set of interlinked functions operating on the same DESeqDataSet object and together implementing a complete statistical workflow.

The main DESeq2 reference is:

Love MI, Huber W, Anders S. Moderated estimation of fold change and dispersion for RNA-seq data with DESeq2. Genome Biology 15, 550 (2014). doi:10.1186/s13059-014-0550-8

A little historical context

RNA-seq counts are not well described by a simple Gaussian model, and biological replicates usually vary more than expected from a Poisson process. This became particularly important in early RNA-seq experiments, where only a few biological replicates per condition were common.

A major step was therefore to model RNA-seq as overdispersed count data and to borrow information across thousands of genes instead of estimating the variance of every gene completely independently.

Period / framework Main idea Why it mattered
Early simple approaches Poisson models, transformed expression values, or tests not designed specifically for overdispersed sequencing counts Often underestimated biological variability or handled the mean-variance relationship poorly
edgeR / DESeq (DESeq1) Negative-binomial models and sharing information across genes to estimate variability with few replicates Made biological replication and overdispersion central to RNA-seq inference
DESeq2 Negative-binomial GLMs, moderated gene-wise dispersion estimates, model-based coefficient SEs, Wald/LRT inference, flexible design formulas, independent filtering and outlier diagnostics Generalized the approach into a more flexible regression framework suitable for both simple and multi-factor experiments

The original DESeq method already modeled counts with a negative-binomial distribution and estimated the relationship between mean expression and variability across genes using a smooth trend Anders & Huber, 2010. DESeq2 retained the same broad principle but moved the analysis into a unified negative-binomial generalized linear model (GLM) framework and introduced improved shrinkage/moderation of dispersion and, historically, fold-change estimates. Current DESeq2 separates log2-fold-change shrinkage into lfcShrink() rather than applying it automatically during the main Wald test.

Note

Take-home: DESeq2 did not invent RNA-seq differential expression, and it is not the only valid method. We use it because it is a mature, widely adopted implementation of the general principle: model count data, estimate biological variability using information shared across genes, fit the experimental design, and test the effect of interest.

5.2 The DESeq2 idea without the mathematics

DESeq2 starts from raw integer counts. The counts must remain on a count scale because the model is built for discrete sequencing counts. Do not convert the input matrix to CPM, TPM, RPKM, percentages, log values, or bigWig signal before fitting DESeq2.

Individual libraries are sequenced to different depths. A count of 500 in one sample therefore does not necessarily represent the same abundance as a count of 500 in another sample. DESeq2 first estimates a sample-specific size factor so that differences in overall library size are accounted for internally.

For each gene, the conceptual workflow is:

RAW INTEGER COUNTS
        |
        v
account for differences in library size
        |
        v
fit a GLM describing the EXPECTED COUNT
for each sample from the experimental design
        |
        v
ask how much the OBSERVED COUNTS vary
around those fitted expectations
        |
        v
model that variability with a gene-specific
NEGATIVE-BINOMIAL DISPERSION alpha_i
        |
        v
stabilize alpha_i by borrowing information
from the genome-wide mean-dispersion trend
        |
        v
use the stabilized dispersion + fitted means
+ design + number of biological replicates
        |
        v
estimate the uncertainty of the condition effect:
SE(log2FC)
        |
        v
z = log2FC / SE(log2FC)
        |
        v
Wald-test p-value
        |
        v
multiple-testing correction
        |
        v
adjusted p-value / FDR

Three quantities should remain conceptually distinct:

Quantity Interpretation
Expected count Count predicted by the fitted model for a gene in a sample after accounting for library size and the design
Dispersion alpha_i How variable the observed counts for gene i are around their fitted expectations
SE(log2FC) How uncertain we are about the estimated condition effect

With only a few biological replicates, a completely independent dispersion estimate for every gene would be unstable. DESeq2 therefore learns the typical relationship between mean expression and dispersion across all genes and moderates each gene-specific dispersion toward that trend. By default DESeq2 tries a parametric mean-dispersion trend; if that shape is unsuitable, a local fit can be used instead.

The stabilized dispersion is not itself the standard error of the fold change. It is one of the quantities used by the fitted GLM to determine the uncertainty of the estimated coefficient.

5.3 The experimental design: decide what the model should explain

The design formula is not a software detail. It is the statistical representation of the experimental structure.

A good rule is:

Include variables that represent real, identifiable sources of systematic variation that should be accounted for while estimating the biological effect of interest. Do not add columns simply because they exist in the metadata.

The experimental unit matters more than the column name. In particular, a metadata column called replicate does not automatically belong in the model.

Experimental structure Typical DESeq2 design Principle
Two independent conditions with biological replicates ~ condition Replicate numbers are identifiers, not covariates
Same patient / donor / animal measured in both conditions ~ subject + condition Subject is a blocking factor because measurements are paired
Samples processed in different technical batches, with conditions represented across batches ~ batch + condition Account for systematic batch variation while estimating condition
Genotype and treatment where treatment effect may differ by genotype ~ genotype + treatment + genotype:treatment Use an interaction only when the scientific question is about different responses
Same biological library sequenced twice Collapse technical runs before DESeq2 Multiple sequencing runs of the same library are not independent biological replicates
Batch and condition perfectly confounded No valid formula can separate them The experiment itself does not contain enough information to estimate both effects

Biological replicate versus blocking factor

For this workshop we have a 2 × 2 biological design: genotype (WT or ΔHP1021) and treatment (control or treated), with three independent biological replicates in each combination. Replicate numbers are identifiers; replicate 1 in one RNA-seq group is not a repeated measurement of replicate 1 in another group.

For teaching, we encode genotype and treatment together as one four-level factor:

WT          = WT, untreated
WTS         = WT, treated
ΔHP1021     = ΔHP1021, untreated
ΔHP1021S    = ΔHP1021, treated

and fit the simple model:

design = ~ condition

This parameterization makes the biologically useful pairwise contrasts explicit: WT vs ΔHP1021, WTS vs ΔHP1021S, WTS vs WT, and ΔHP1021S vs ΔHP1021. We do not add replicate number as a blocking factor. If the scientific question were specifically whether the treatment response differs by genotype, we would instead formulate the factorial interaction ~ genotype + treatment + genotype:treatment.

By contrast, if the experiment contained samples from the same patient before and after treatment, the patient identity would represent genuine pairing and we would use:

design = ~ patient + condition

General principles when choosing covariates

  • Define the biological question and experimental unit first, then write the design.
  • Include known batch or subject effects when they are biologically/statistically meaningful and not perfectly confounded with the condition of interest.
  • Do not treat technical replicates as independent biological evidence.
  • Do not include an arbitrary replicate number simply to “account for replicates”; biological replication is what allows dispersion to be estimated in the first place.
  • Avoid adding many covariates to a very small experiment unless they are essential: every additional coefficient consumes information.
  • Prefer variables specified from the experimental design or strong prior knowledge, not variables selected because they make the desired p-values smaller.
  • If a covariate is perfectly confounded with condition, no statistical model can recover the two effects separately; this is a design problem rather than a DESeq2 problem.
  • For convenience and interpretability, put the main variable of interest last in the formula and set its reference level explicitly.
Warning

Model design is part of the experiment. A sophisticated model cannot recover information that was never separated experimentally. If all controls were processed in batch 1 and all treated samples in batch 2, batch and condition are indistinguishable.

5.4 Why PCA before differential expression?

Before testing genes one by one, we should first ask whether the samples themselves behave as expected.

NGS experiments typically contain thousands of measured features but relatively few samples. We therefore need sample-level exploratory analyses that summarize the global structure of the data without starting from a list of significant genes.

Principal component analysis (PCA) is widely used for this purpose because it is unsupervised: the PCA calculation does not know which samples are controls, treated, batch 1, batch 2, or potential outliers. It simply finds the major directions of variation across the expression profiles. We add biological labels only afterwards to interpret the pattern.

In RNA-seq QC, PCA helps us ask:

  • Do biological replicates occupy similar regions of expression space?
  • Is the largest source of variation related to the biological condition we intended to study?
  • Is there an unexpected batch structure?
  • Does one sample behave very differently from all others?
  • Could a sample label have been swapped?
  • Is a putative outlier also unusual in mapping rate, library size, gene assignment, or other QC metrics?

For PCA, each sample is treated as one point described by the expression of many genes. PCA replaces those thousands of gene dimensions with a smaller set of principal components. PC1 captures the largest direction of sample-to-sample variation, PC2 the largest remaining independent direction, and so on. A PC1-versus-PC2 plot is therefore a low-dimensional view of the strongest global structure in the experiment.

Important

PCA is a diagnostic, not an automatic outlier-removal algorithm.

A sample should not be removed simply because it lies far from the other points or because removing it improves the differential-expression result. A PCA outlier should trigger investigation of sample identity, FASTQ/BAM QC, mapping, strandedness, gene assignment, library size, batch metadata, and laboratory notes. Exclusion is defensible when there is evidence of technical failure, contamination, mislabelling, or another pre-specified reason. If the sample reflects genuine biological heterogeneity, removing it can bias the analysis.

In this workshop we use log2(normalized_counts + 1) for PCA because it keeps the transformation transparent. In larger RNA-seq analyses, DESeq2 vst() or rlog() are commonly used to reduce the strong dependence of variance on mean expression before PCA and clustering.

5.5 Wald test, multiple testing and FDR

After the model has estimated the condition effect and its standard error for each gene, the Wald statistic is simply the effect expressed in units of its uncertainty:

z = log2FC / SE(log2FC)

A large absolute z means that the estimated effect is large relative to the uncertainty of that estimate. Under the null hypothesis of no condition effect, DESeq2 compares this statistic with the standard normal distribution to obtain a p-value.

RNA-seq tests hundreds or thousands of genes simultaneously. Even if no true biological effects existed, some small p-values would occur by chance. DESeq2 therefore reports a Benjamini-Hochberg adjusted p-value (padj), which is used to control the false discovery rate (FDR).

At an FDR threshold of 5%, the procedure aims to keep the expected fraction of false discoveries among the genes called significant at about 5% or below. This is not the same as saying that each individual gene with padj < 0.05 has a 5% probability of being a false positive.

5.7 Read the analysis in the same order DESeq2 performs it

The code above contains many R commands, but conceptually the workflow is short.

Step 1: raw count matrix + metadata

The rows are genes and the columns are samples. The counts remain integer fragment counts from featureCounts. The metadata assigns every sample to one of the four groups WT, WTS, ΔHP1021, or ΔHP1021S.

The order must match exactly:

count-matrix columns  ==  metadata rows

DESeq2 does not infer sample identity from filenames once the matrix has been constructed.

Step 2: size factors

Libraries differ in sequencing depth and overall count scale. DESeq2 estimates one size factor per sample so that counts from different libraries can be compared on a common scale.

We save normalized counts for exploration and visualization, but the statistical model still uses the original raw counts together with the size factors.

Step 3: PCA as sample-level QC

We run PCA before interpreting differential expression. The important questions are not whether the conditions separate perfectly, but whether the global sample structure makes biological and technical sense.

For this twelve-sample experiment:

12 samples x many genes
        |
        v
log2-normalized expression
        |
        v
PCA
        |
        v
PC1 / PC2 sample map

Each point is one sample. Samples close together have broadly similar global expression profiles; samples far apart differ across many genes. Because PCA is unsupervised, unexpected separation can reveal batch effects or sample problems that would otherwise be hidden by looking only at the final DEG table.

Step 4: fit the DESeq2 model

For this experiment we use:

design = ~ condition

The model contains the four biological groups directly. We then request explicit contrasts according to the question:

WT versus ΔHP1021          -> genotype difference without S treatment
WTS versus ΔHP1021S        -> genotype difference with S treatment
WTS versus WT              -> treatment response in WT
ΔHP1021S versus ΔHP1021    -> treatment response in ΔHP1021

The sign of log2FoldChange always follows the numerator and denominator written in the selected contrast. For example, positive values in WT versus ΔHP1021 mean higher expression in WT.

When DESeq() runs, it carries out the major stages discussed above: size-factor estimation, gene-wise dispersion estimation, fitting/stabilizing the genome-wide dispersion trend, negative-binomial GLM fitting, and coefficient testing.

Step 5: inspect the dispersion plot

The dispersion plot shows how gene-level variability changes with mean expression and how noisy gene-wise dispersion estimates are stabilized using information from the full set of genes.

The point is not to memorize the exact curve. The important idea is:

genes with similar expression provide information about the amount of variability we should expect when replication is limited.

Step 6: interpret the results table

The main DESeq2 columns are:

Column Meaning
baseMean Mean normalized expression across samples
log2FoldChange Estimated effect for the specific contrast being inspected; its sign follows the numerator versus denominator
lfcSE Standard error of that estimated log2 fold change
stat Wald statistic: effect divided by its SE
pvalue Unadjusted p-value for this gene
padj Multiple-testing-adjusted p-value used for FDR control

The effect size and statistical evidence are related but not interchangeable. A large fold change can be uncertain when counts are low or variable, while a modest fold change can be estimated precisely when counts are high and replicates are consistent.

Step 7: use plots to answer different questions

PCA asks whether the samples show sensible global structure before gene-level interpretation.

Dispersion plot asks whether the estimated gene variability follows a coherent mean-dispersion relationship and shows the moderation performed by DESeq2.

MA-like plot shows effect size against mean expression:

x-axis = mean normalized expression
 y-axis = log2 fold change

It is useful for seeing whether large fold changes are concentrated among low-count genes and for inspecting the dependence of effect estimates on abundance.

Volcano plot combines effect size and statistical evidence:

x-axis = log2 fold change
 y-axis = -log10 adjusted p-value

A volcano plot is a presentation of the fitted results, not the statistical model itself. Always interpret it together with the count structure, PCA, dispersion, and MA plot.

11. Self-check questions

  1. Why is Bowtie2 suitable for this bacterial RNA-seq dataset but not the usual default for mammalian spliced RNA-seq?
  2. What is the difference between SAM, BAM, and BAI?
  3. Which mapping and pairing metrics would you inspect before trusting the count matrix?
  4. Why does this directional library require featureCounts -s 2, and how did we validate that choice?
  5. Why can a sample map well but still have poor featureCounts assignment?
  6. Why does DESeq2 require raw integer counts rather than CPM, TPM, or bigWig signal?
  7. Why does the workshop use a four-level ~ condition design, and why is replicate number not included as a blocking factor? When would a genotype:treatment interaction be required instead?
  8. When would ~ patient + condition or ~ batch + condition be appropriate?
  9. What does the dispersion parameter represent intuitively, and why is information borrowed across genes?
  10. What does PCA tell us before differential-expression testing, and why should PCA alone not be used to remove a sample?
  11. What is the difference between log2FoldChange, lfcSE, pvalue, and padj?
  12. What does an FDR threshold of 5% mean at the level of a set of discoveries?
