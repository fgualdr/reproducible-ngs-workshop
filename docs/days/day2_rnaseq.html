3. Reference-based RNA-seq FASTQ mapping

RNA-seq mapping asks where each sequenced read, or read pair, fits on a reference sequence. The input is FASTQ. The output is an alignment file that records the genomic position and alignment details for each read.

Mapping starts from:

  • trimmed FASTQ files from Day 1;
  • a reference genome FASTA;
  • an aligner index built from that FASTA.

The index does not change the genome. It creates extra files that allow the aligner to search the genome quickly.

3.1 Alignment versus pseudoalignment

Full aligners try to place each read or read pair at one or more genomic or transcriptomic coordinates. A common strategy is seed-and-extend:

  1. split or sample short exact pieces of the read called seeds;
  2. use the index to find candidate reference positions for those seeds;
  3. extend candidate alignments across the full read;
  4. score each alignment using matches, mismatches, gaps, clipping, base qualities, and sometimes paired-end consistency;
  5. report the best alignment or alignments, usually with a mapping quality score.

The exact scoring system differs by tool. In general, a better score means the read agrees better with the reference. If several locations have similar scores, the read is ambiguous and the mapping quality is lower. For paired-end reads, aligners also use whether both mates map with the expected orientation and distance.

Splice-aware RNA-seq aligners add another idea: a read may align across two exons with a skipped intron between them. These aligners can represent exon-exon junctions in the alignment. This is essential for many eukaryotic RNA-seq datasets but unnecessary for this bacterial workshop.

Pseudoaligners and quasi-aligners usually do not try to report one exact genomic coordinate for every read. Instead, they infer which transcript or set of transcripts is compatible with each read or fragment. This is very fast and useful for transcript quantification, but it is a different workflow from creating genome-coordinate BAM files for IGV and feature counting.

Common genome aligners include:

Tool Main alignment idea Splice-aware? Main strengths Main limitations Take home
Bowtie2 FM-index genome aligner using seed-and-extend search and gapped alignment scoring No Fast, simple, low memory, good for small genomes; supports mismatches, gaps, clipping, and paired-end constraints; produces coordinate BAM files Does not model exon-exon junctions as splicing events; eukaryotic exon-internal reads can map, but junction-spanning reads are not handled like a splice-aware RNA-seq aligner Good default here for bacterial RNA-seq and ChIP-seq because the genome is small and introns are not present
BWA-MEM/BWA-MEM2 Burrows-Wheeler genome aligner optimized for longer reads using maximal exact matches as seeds No Very robust general-purpose DNA aligner; common for variant calling, genomic DNA, ChIP-seq, ATAC-seq, and microbial genome alignment Not designed to discover splice junctions; less commonly used as the main tool for gene-level RNA-seq counting Conceptually similar to Bowtie2 as a non-splice-aware genome aligner, but more associated with DNA-seq and longer-read genomic alignment
STAR Splice-aware RNA-seq genome aligner using an uncompressed suffix-array style index and two-pass-style junction discovery options Yes Extremely fast for large eukaryotic RNA-seq; strong exon-junction detection; widely used for mammalian gene-count workflows High memory use; more complex; unnecessary for bacterial genomes without introns A standard choice for mammalian or other eukaryotic RNA-seq when exon-exon junctions matter
HISAT2 Splice-aware RNA-seq genome aligner using hierarchical FM indexes, with optional transcript/splice-site guidance Yes Much lower memory than STAR; good eukaryotic splice-aware alignment; can use known splice sites while still discovering novel junctions Often slower than STAR for large projects; still more complex than needed for this bacterial workflow A compact splice-aware alternative for eukaryotic RNA-seq, especially when memory is limited

Common pseudoalignment or quasi-alignment tools include:

Tool Method used by the tool Advantages Disadvantages When to use it
Salmon Quasi-mapping or selective alignment to transcript sequences Very fast transcript/gene quantification Usually does not create a genome-coordinate BAM for IGV; requires transcriptome and transcript-to-gene handling Transcript-level quantification
Kallisto Pseudoalignment to transcript compatibility classes Very fast and lightweight Usually does not create a genome-coordinate BAM for IGV; less natural for the BAM-first workflow used here Fast transcript quantification

In this workshop we use Bowtie2 because H. pylori has a small bacterial genome, there are no introns to model, and we want coordinate-sorted BAM files that can also be inspected later in IGV.

3.2 SAM and BAM files

The general alignment file created by an aligner is SAM:

Sequence Alignment/Map format

SAM is a plain-text alignment format. BAM is the compressed binary version of SAM. In practice, we usually create a temporary SAM file, convert it to BAM, sort the BAM by genomic coordinate, and create a BAM index file:

sample.sam
  -> sample.sorted.bam
  -> sample.sorted.bam.bai

The sorted BAM is compact and fast for downstream tools. The .bai index lets software jump directly to one genomic region without reading the whole BAM file.

A BAM file contains one alignment record per read alignment. The common SAM/BAM fields are:

Field Meaning
QNAME Read name from the FASTQ identifier
FLAG Bit-coded alignment status, such as paired, mapped, reverse strand, secondary, supplementary, duplicate
RNAME Reference sequence name, such as chromosome or contig
POS 1-based leftmost alignment coordinate
MAPQ Mapping quality, a score for confidence in the reported position
CIGAR Compact description of matches, insertions, deletions, clipping, and skipped reference regions
RNEXT Reference name for the mate read in paired-end data
PNEXT Position of the mate read
TLEN Template length inferred from the read pair
SEQ Read sequence
QUAL Base quality string

The CIGAR string is important for RNA-seq. In bacterial RNA-seq, reads usually align continuously because bacterial genes usually do not contain spliceosomal introns. In eukaryotic RNA-seq, a read can span an exon-exon junction. Splice-aware aligners represent this with an N operation in the CIGAR string, meaning a skipped region in the reference. Other CIGAR operations include M for aligned match/mismatch, I for insertion relative to the reference, D for deletion relative to the reference, and S for soft clipping.

Aligners also write optional tags after the common columns. These tags are tool-specific. Common examples include edit distance, alignment score, number of possible alignments, or strand information. This is one reason BAM files from different aligners can contain the same core information but different additional descriptors.

3.3 How paired-end reads are stored in BAM

Paired-end FASTQ files have one R1 file and one R2 file. In the BAM file, the two ends are not stored as one combined row. They are stored as two separate alignment records with the same read name (QNAME), one record for read 1 and one record for read 2.

The pair relationship is encoded in the BAM fields:

BAM field Paired-end meaning
QNAME Same read-pair identifier for R1 and R2
FLAG Says whether this record is read 1 or read 2, whether the mate is mapped, whether the pair is properly paired, and which strand each end maps to
RNAME and POS Reference name and position for this read end
RNEXT and PNEXT Reference name and position for the mate read
TLEN Inferred template length, meaning the genomic span covered by the read pair
CIGAR Alignment shape for this read end only

For a simple properly paired fragment, R1 and R2 usually map to nearby positions on opposite strands with an expected orientation. The two BAM records point to each other through the mate fields. When we sort a BAM by coordinate, the two mates may no longer be next to each other in the file, but the mate information remains encoded in the records.

This is why paired-end tools can count fragments rather than individual read ends. Later, featureCounts uses the paired-end information to assign one fragment-level count to a gene instead of counting R1 and R2 separately.

3.5 Map RNA-seq reads

The mapping script uses the Day 1 trimmed RNA-seq FASTQ files. It writes Bowtie2 logs, sorted BAM files, BAM indexes, and samtools mapping summaries.

Create scripts/day2_rnaseq/02_map_bowtie2_sort_index.sh:

nano scripts/day2_rnaseq/02_map_bowtie2_sort_index.sh

Paste this script:

#!/usr/bin/env bash
set -euo pipefail

fastq_dir="results/day1_qc/trimmed_fastq/rnaseq"
index_prefix="reference_genome/bowtie2_index/genome"
bam_dir="results/day2_rnaseq/bam"
log_dir="results/logs/day2"

mkdir -p "${bam_dir}" "${log_dir}"

for read1 in "${fastq_dir}"/*_R1.trimmed.fastq.gz
do
  [[ -e "${read1}" ]] || continue

  read2="${read1/_R1.trimmed.fastq.gz/_R2.trimmed.fastq.gz}"
  sample_id="$(basename "${read1}" _R1.trimmed.fastq.gz)"
  sam_file="${bam_dir}/${sample_id}.sam"
  bam_file="${bam_dir}/${sample_id}.sorted.bam"
  filtered_bam="${bam_dir}/${sample_id}.filtered.bam"

  if [[ ! -f "${read2}" ]]; then
    echo "ERROR: paired read not found for ${read1}" >&2
    exit 1
  fi

  echo "Mapping ${sample_id}"
  bowtie2 \
    -x "${index_prefix}" \
    -1 "${read1}" \
    -2 "${read2}" \
    -p 2 \
    -S "${sam_file}" \
    2> "${log_dir}/${sample_id}.bowtie2.log"

  samtools sort \
    -@ 2 \
    -o "${bam_file}" \
    "${sam_file}"

  samtools index "${bam_file}"

  samtools flagstat "${bam_file}" > "${log_dir}/${sample_id}.flagstat.txt"

  samtools view \
    -@ 2 \
    -b \
    -q 10 \
    -f 2 \
    -F 2828 \
    -o "${filtered_bam}" \
    "${bam_file}"

  samtools index "${filtered_bam}"

  samtools flagstat "${filtered_bam}" > "${log_dir}/${sample_id}.filtered.flagstat.txt"

  rm -f "${sam_file}"
done

Run it:

docker run --rm \
  --platform linux/amd64 \
  -v "$PWD:/work" \
  -w /work \
  docker.io/fgualdr/ngs-bowtie2-samtools:latest \
  bash scripts/day2_rnaseq/02_map_bowtie2_sort_index.sh

Check the mapping logs:

cat results/logs/day2/*.bowtie2.log

Bowtie2 logs report useful mapping metrics, including:

Metric What it tells us
Number of input read pairs Whether the aligner saw the expected amount of data
Concordantly aligned pairs Read pairs that align with expected orientation and distance
Discordantly aligned pairs Pairs that align but not in the expected paired-end pattern
Unaligned reads or pairs Reads that did not match the reference well enough

Low mapping percentage can indicate a wrong reference, contamination, poor read quality, wrong sample labels, incomplete trimming, or strong rRNA/technical content.

4. Clean BAM files with samtools

samtools is the standard command-line tool for viewing, sorting, indexing, summarizing, and filtering SAM/BAM files.

In this workflow we use it for:

  • converting the temporary SAM output into sorted BAM;
  • creating .bai BAM index files;
  • summarizing BAM files with samtools flagstat;
  • filtering alignments before counting.

The script from section 3 already runs this cleanup step after mapping:

samtools view \
  -@ 2 \
  -b \
  -q 10 \
  -f 2 \
  -F 2828 \
  -o "${filtered_bam}" \
  "${bam_file}"

This keeps alignments with mapping quality at least 10 and keeps properly paired reads. It removes common records that should not be counted as ordinary primary mapped read pairs, such as unmapped reads, reads with unmapped mates, secondary alignments, failed-QC reads, and supplementary alignments.

SAM flags are bit-coded, so they are not intuitive at first. We will not memorize them. When you need to inspect or design a flag filter, use a flag converter such as:

https://broadinstitute.github.io/picard/explain-flags.html

Check the samtools flagstat summaries:

ls -lh results/logs/day2/*.flagstat.txt
cat results/logs/day2/*.flagstat.txt

Compare the unfiltered and filtered summaries:

cat results/logs/day2/*.filtered.flagstat.txt

These files help answer:

  • how many reads were mapped;
  • how many read pairs were properly paired;
  • how many alignments were removed by filtering;
  • whether one sample behaves very differently from the others.

We do not remove coordinate-marked duplicates by default in this teaching RNA-seq workflow. In RNA-seq, many reads at the same location can reflect high expression, not only PCR duplication. Duplicate removal can bias highly expressed genes, especially in compact bacterial genomes.

5. Count reads per gene with featureCounts

After mapping, we want one number per gene per sample. That number is the number of fragments assigned to the gene annotation.

There are several ways to count reads in features:

Counting route How it works Advantage Limitation
featureCounts Command-line tool counts overlaps between BAM alignments and GFF/GTF features Fast, simple, widely used, good for teaching Requires correct annotation fields and strand settings
HTSeq-count Python tool counts reads against annotation features Clear conceptual model Slower and less convenient for many samples
R/Bioconductor overlap counting Use packages such as GenomicAlignments, GenomicFeatures, and summarizeOverlaps Very flexible and reproducible inside R More code and more Bioconductor concepts
Transcript quantifiers Salmon or Kallisto quantify transcript compatibility directly Very fast for transcriptome workflows Different workflow; not the BAM-first route used here

For practical purposes, we use featureCounts with the downloaded annotation:

filtered BAM + reference_genome/annotation.gff3
  -> featureCounts
  -> one all-sample featureCounts table
  -> one simple gene-by-sample count matrix

For paired-end RNA-seq, we count fragments rather than individual read ends:

  • -p tells featureCounts to count fragments from paired-end reads;
  • -B requires both ends to be aligned;
  • -C avoids counting chimeric fragments.

The command below uses -t gene -g ID, which means:

  • count reads overlapping GFF3 records whose feature type is gene;
  • use the ID attribute from the GFF3 file as the gene identifier.

This is a practical choice for the NCBI-style bacterial GFF3 used in this workshop. If an annotation uses a different feature type, such as CDS, or a different gene identifier attribute, these two options must be changed.

The command below does not set -s, so featureCounts treats the library as unstranded. If the actual RNA-seq protocol is stranded, count assignment can be badly wrong unless -s 1 or -s 2 is used after checking the library orientation in the metadata or protocol.

Create scripts/day2_rnaseq/03_featurecounts_all_samples.sh:

nano scripts/day2_rnaseq/03_featurecounts_all_samples.sh

Paste this script:

#!/usr/bin/env bash
set -euo pipefail

annotation="reference_genome/annotation.gff3"
bam_dir="results/day2_rnaseq/bam"
counts_dir="results/day2_rnaseq/counts"
log_dir="results/logs/day2"
featurecounts_out="${counts_dir}/featureCounts_all_samples.txt"
count_matrix="${counts_dir}/gene_count_matrix.tsv"

mkdir -p "${counts_dir}" "${log_dir}"

if [[ ! -f "${annotation}" ]]; then
  echo "ERROR: annotation file not found: ${annotation}" >&2
  exit 1
fi

# Collect all filtered BAM files
bam_files=("${bam_dir}"/*.filtered.bam)

if [[ ! -e "${bam_files[0]}" ]]; then
  echo "ERROR: No filtered BAM files found in ${bam_dir}" >&2
  exit 1
fi

echo "Counting reads across ${#bam_files[@]} samples..."

featureCounts \
  -T 2 \
  -p \
  -B \
  -C \
  -t gene \
  -g ID \
  -a "${annotation}" \
  -o "${featurecounts_out}" \
  "${bam_files[@]}" \
  2>&1 | tee "${log_dir}/featureCounts_all_samples.log"

# Convert the full featureCounts table into the simple gene x sample matrix used by DESeq2.
awk 'BEGIN { FS = OFS = "\t" }
  /^#/ { next }
  $1 == "Geneid" {
    printf "gene_id"
    for (i = 7; i <= NF; i++) {
      sample = $i
      sub(/^.*\//, "", sample)
      sub(/[.]filtered[.]bam$/, "", sample)
      printf OFS sample
    }
    printf "\n"
    next
  }
  {
    printf $1
    for (i = 7; i <= NF; i++) {
      printf OFS $i
    }
    printf "\n"
  }' "${featurecounts_out}" > "${count_matrix}"

echo "Wrote ${featurecounts_out}"
echo "Wrote ${count_matrix}"

Run it:

  --platform linux/amd64 \
  -v "$PWD:/work" \
  -w /work \

A sample can map well but count poorly if the annotation does not match the genome, the wrong feature type is used, the library strandedness is wrong, or many reads fall outside annotated genes.

The result should look like this:

geneB    5                8                6

Keep this matrix as raw integer counts. Do not convert it to CPM, TPM, RPKM, or bigWig signal before DESeq2.

Approximate sanity checks before moving to DESeq2:

Check Reasonable teaching-workflow expectation If it looks bad
Bowtie2 overall alignment rate Often high for a small bacterial genome when the reference and sample labels are correct Check wrong reference, contamination, mixed samples, or failed trimming
Properly paired reads after filtering Most mapped pairs should remain properly paired Check R1/R2 pairing, sample names, insert size, or over-strict filtering
featureCounts assignment rate A large fraction of aligned fragments should assign to annotated genes in a compact bacterial genome Check annotation/reference mismatch, -t/-g options, strandedness, or chromosome names
Replicate behavior Replicates should have broadly similar mapping, assignment, and library sizes Recheck sample labels and any sample-specific QC warning

These are qualitative checks, not pass/fail statistical tests. A clearly different sample should be investigated before interpreting differential expression.

6. Raw count matrix and DESeq2 differential expression

The count matrix has genes as rows and samples as columns:

features x samples

Before modeling, check whether the experiment still makes sense:

  • How many reads were present after trimming?
  • What percentage mapped to the genome?
  • What percentage of mapped reads were assigned to genes?
  • Are any samples strong outliers at the mapping or counting stage?
  • Do sample names in the count matrix match the metadata?

If many reads disappear between FASTQ, BAM, and gene counts, do not jump directly to p-values. First check reference version, annotation version, strandedness, sample labels, and logs.

6.1 Statistical idea

For each gene, RNA-seq gives integer counts. A simple Poisson model would assume that the count variance is equal to the count mean. Real RNA-seq data usually vary more than that because of biological variation, library preparation, and sampling effects. This extra variation is called overdispersion.

DESeq2 and edgeR model counts with a negative binomial distribution because it allows the variance to be larger than the mean. A useful simplified version is:

\[ K_{ij} \sim \mathrm{NB}(\mu_{ij}, \alpha_i) \]

where:

  • \(K_{ij}\) is the raw count for gene \(i\) in sample \(j\);
  • \(\mu_{ij}\) is the expected count for that gene and sample;
  • \(\alpha_i\) is the gene-specific dispersion, meaning extra variability beyond simple Poisson sampling.

DESeq2 does not simply run an independent ordinary test for each gene and ignore the rest of the experiment. It uses information across all genes to estimate size factors and to stabilize dispersion estimates. This is important because each gene has only a small number of replicate measurements.

The model includes the experimental design:

design = ~ condition

For each gene, DESeq2 estimates a condition effect. We usually report this as a log2 fold change:

log2FoldChange = expression change for WT_21Oxygen relative to WT_control

DESeq2 also estimates uncertainty for that effect. The lfcSE column is the standard error of the log2 fold change. Intuitively, it reflects how variable the replicate counts are around the fitted model, after normalization and dispersion estimation. Genes with noisy counts, low counts, or inconsistent replicates have less precise fold-change estimates.

The Wald test asks whether the fitted condition effect is clearly different from zero relative to its uncertainty. Because this is done for many genes, DESeq2 reports adjusted p-values (padj) to control the false discovery rate.

6.2 Median-of-ratios normalization

Raw counts depend on library size and composition. DESeq2 estimates a size factor for each sample using the median-of-ratios method. The key assumption is that most genes are not globally changing in the same direction. Under that assumption, the typical gene can be used to estimate how much larger or smaller one library is relative to another.

DESeq2 still uses raw integer counts as input. The normalization factors are estimated inside the model; students should not pre-normalize the matrix before running DESeq2.

6.3 Step-by-step R workflow

Create scripts/day2_rnaseq/04_deseq2_analysis.R:

nano scripts/day2_rnaseq/04_deseq2_analysis.R

Paste this script:

#!/usr/bin/env Rscript

args <- commandArgs(trailingOnly = TRUE)
if (length(args) != 2) {
  stop("Usage: 04_deseq2_analysis.R count_matrix.tsv outdir")
}

required <- c("DESeq2", "ggplot2")
missing <- required[!vapply(required, requireNamespace, logical(1), quietly = TRUE)]
if (length(missing)) {
  stop("Missing R packages: ", paste(missing, collapse = ", "))
}

counts <- read.delim(args[[1]], check.names = FALSE)
outdir <- args[[2]]

dir.create(outdir, recursive = TRUE, showWarnings = FALSE)

rownames(counts) <- counts$gene_id
counts$gene_id <- NULL

sample_ids <- names(counts)
if (length(sample_ids) < 4) {
  stop("Expected RNA-seq samples from at least two conditions with biological replicates")
}

condition <- sub("^[^_]+_[^_]+_", "", sample_ids)
replicate <- sub("^[^_]+_([^_]+)_.*$", "rep\\1", sample_ids)

samples <- data.frame(
  sample_id = sample_ids,
  condition = condition,
  replicate = replicate,
  row.names = sample_ids,
  check.names = FALSE
)

if (length(unique(samples$condition)) < 2) {
  stop("Could not infer at least two conditions from sample names")
}

if (all(c("WT_control", "WT_21Oxygen") %in% samples$condition)) {
  samples$condition <- factor(samples$condition, levels = c("WT_control", "WT_21Oxygen"))
} else {
  samples$condition <- factor(samples$condition)
}

count_mat <- as.matrix(round(counts[, sample_ids, drop = FALSE]))

dds <- DESeq2::DESeqDataSetFromMatrix(
  countData = count_mat,
  colData = samples,
  design = ~ condition
)
dds <- dds[rowSums(DESeq2::counts(dds)) >= 10, ]
dds <- DESeq2::DESeq(dds)

if (all(c("WT_control", "WT_21Oxygen") %in% levels(samples$condition))) {
  res <- as.data.frame(DESeq2::results(dds, contrast = c("condition", "WT_21Oxygen", "WT_control")))
} else {
  res <- as.data.frame(DESeq2::results(dds))
}
res$gene_id <- rownames(res)
write.csv(samples, file.path(outdir, "inferred_sample_design.csv"), row.names = FALSE)
write.table(res, file.path(outdir, "deseq2_results.tsv"), sep = "\t", quote = FALSE, row.names = FALSE)

vsd <- DESeq2::vst(dds, blind = TRUE)

pdf(file.path(outdir, "pca.pdf"))
print(DESeq2::plotPCA(vsd, intgroup = "condition"))
dev.off()

pdf(file.path(outdir, "dispersion_plot.pdf"))
DESeq2::plotDispEsts(dds)
dev.off()

pdf(file.path(outdir, "ma_plot.pdf"))
DESeq2::plotMA(res)
dev.off()

volcano <- ggplot2::ggplot(res, ggplot2::aes(x = log2FoldChange, y = -log10(padj))) +
  ggplot2::geom_point(alpha = 0.6, size = 1) +
  ggplot2::theme_bw() +
  ggplot2::labs(x = "log2 fold change", y = "-log10 adjusted p-value")

ggplot2::ggsave(file.path(outdir, "volcano.pdf"), volcano, width = 6, height = 5)
writeLines(capture.output(sessionInfo()), file.path(outdir, "sessionInfo.txt"))

The script does these steps:

R step Meaning
Read raw count matrix Load integer counts from featureCounts
Infer sample design Build condition and replicate from sample names such as WT_1_WT_control
Create DESeqDataSet Combine counts, metadata, and design formula
Filter very low-count genes Remove genes with too little information
Run DESeq() Estimate size factors, dispersions, and condition effects
Save results Write log2 fold changes, standard errors, p-values, and adjusted p-values
Make diagnostic plots PCA, dispersion plot, MA plot, and volcano plot

The script writes the inferred design table to:

results/day2_rnaseq/deseq2/inferred_sample_design.csv

Always inspect this file. If condition labels are wrong, the sample names are not following the expected Day 1 pattern.

Common DESeq2 result columns:

Column Meaning
baseMean Mean normalized count across samples
log2FoldChange Estimated condition effect on the log2 scale
lfcSE Standard error of the log2 fold change
stat Wald test statistic
pvalue Raw p-value
padj Multiple-testing adjusted p-value

Important plots:

Plot What to check
PCA Whether biological replicates cluster together and whether conditions separate
Dispersion plot Whether gene-wise dispersions follow a reasonable mean-dispersion trend
MA plot Whether log2 fold changes are centered and whether large changes are mostly low-count genes
Volcano plot Which genes combine large effect size with small adjusted p-value

Do not treat the volcano plot as the analysis itself. It is a summary of the fitted model results.

7. Optional: make RNA-seq bigWig tracks

bigWig files store genome-wide coverage signal. They are useful for IGV inspection but are not inputs to DESeq2.

Create scripts/day2_rnaseq/05_make_bigwig_bamcoverage.sh:

nano scripts/day2_rnaseq/05_make_bigwig_bamcoverage.sh

Paste this script:

#!/usr/bin/env bash
set -euo pipefail

bam_dir="results/day2_rnaseq/bam"
out_dir="results/day2_rnaseq/bigwig"

mkdir -p "${out_dir}"

bam_files=("${bam_dir}"/*.filtered.bam)

if [[ ! -e "${bam_files[0]}" ]]; then
  echo "ERROR: No filtered BAM files found in ${bam_dir}" >&2
  exit 1
fi

for bam in "${bam_files[@]}"
do
  sample_id="$(basename "${bam}" .filtered.bam)"

  bamCoverage \
    -b "${bam}" \
    -o "${out_dir}/${sample_id}.cpm.bw" \
    --normalizeUsing CPM \
    --binSize 10 \
    --numberOfProcessors 2
done

8. Summarize Day 2 logs with MultiQC

MultiQC collects tool logs into one HTML report. This makes it easier to compare samples side by side instead of opening each Bowtie2, samtools, and featureCounts log separately.

Create scripts/day2_rnaseq/06_multiqc_day2.sh:

nano scripts/day2_rnaseq/06_multiqc_day2.sh

Paste this script:

#!/usr/bin/env bash
set -euo pipefail

log_dir="results/logs/day2"
counts_dir="results/day2_rnaseq/counts"
qc_dir="results/day2_rnaseq/qc"

mkdir -p "${qc_dir}"

if [[ ! -d "${log_dir}" ]]; then
  echo "ERROR: Day 2 log directory not found: ${log_dir}" >&2
  exit 1
fi

if ! compgen -G "${log_dir}/*" > /dev/null; then
  echo "ERROR: No Day 2 logs found in ${log_dir}" >&2
  exit 1
fi

multiqc \
  "${log_dir}" \
  "${counts_dir}" \
  --outdir "${qc_dir}" \
  --filename multiqc_report.html \
  --force
